# 1차 진단서 — 2026-09-12

## 이용 흐름

홈에서 주소와 매도·철거·보유·고민 중 중 하나를 선택하면 `/diagnose`로 이동한다. 서버에서 찾은 지번·도로명주소를 사용자에게 확인받은 뒤 건물·토지·개별주택가격 기록을 병렬 조회해 결과를 보여준다. 결과에서 방향을 바꿀 수 있고, `사진·추가 정보 보내기`를 누르면 주소와 현재 선택을 `/apply`에 전달한다.

입력값과 결과는 React context 메모리에만 둔다. 새로고침하면 초기화되며 URL·localStorage·sessionStorage에 주소를 넣지 않는다. 1차 조회는 DB 신청/진단서 생성, 관리자 승인, 이메일 발송을 하지 않는다. 기존 `/report/[id]`의 issued 승인 조건은 그대로다.

## 조회 범위와 상태

- 주소: 기존 Juso 또는 Kakao 서버 설정 사용. 정확/도로명/유사 결과 모두 명시적으로 확인받는다. 확인 요청에서도 서버가 주소를 다시 조회하고 필지번호를 비교한다.
- 기본 기록: 기존 VWorld 건축물·토지특성·개별주택가격 어댑터 사용. 최근 건물 기록이 필지 내 전체 건물 합계라는 보장은 없으므로 대장 원본 대조 안내를 함께 보여준다.
- 레코드별 `known`, `empty`, `error`를 분리한다. 빈 건축물 응답은 건물이 없음/철거 완료로 판정하지 않는다. 자료 기준연도와 출처를 표시한다.
- 법률/세금/매도 가능 등급 판정, 실제 매도가/공사비 예측, 사진 AI 분석은 실행하지 않는다. 계산기는 사용자 입력을 사용하고 미입력 금액은 미확인으로 남긴다.
- 포항 필지가 확인된 경우에만 기존 지원사업 안내를 붙인다. 지원 대상·예산·선정 여부를 자동 확정하지 않는다. 타 지역과 비단독주택에는 범위 확인 안내를 표시한다.
- 주소 없음, 서비스 조회 실패, 요청량 제한을 구분한다. 실패 뒤 사용자가 고르면 `조회 미완료 · 확인 순서 안내`로 일반적인 다음 행동을 볼 수 있다. 가상 데이터를 실제 조회 결과로 대체하지 않는다.

## 운영

필요 환경변수: `ADDRESS_PROVIDER`, 해당 제공자의 `JUSO_CONFM_KEY` 또는 `KAKAO_REST_KEY`, `VWORLD_KEY`, 필요시 `VWORLD_DOMAIN`. 키는 서버에서만 사용한다. 로컬 `.env.local`에는 기존 프로젝트에서 공공자료 조회용 설정만 가져왔으며 신청 DB·메일·관리자 설정은 가져오지 않았다. `.env.local`은 git 제외 대상이다.

각 조회 단계에 12초 상한을 둔다. 기존 제공자 HTTP 요청에는 10초 타임아웃이 있다. 완료된 다른 소스는 실패한 소스 때문에 버리지 않는다. 오류 원문·키·연락처는 1차 결과에 포함하지 않는다.

서버 인스턴스마다 동시 조회 8개, 접속별 1분 20회 제한을 적용한다. 접속 식별은 임시 난수를 포함한 해시를 사용하고 1분 후 제거한다. 이는 다중 인스턴스에 걸친 전역 제한은 아니므로 트래픽 확대 시 공용 제한 저장소나 호스팅 측 제한이 필요하다.

2026-09-12 검증: 22개 테스트와 프로덕션 빌드 통과. 포항시청의 공개 주소로 주소 확인과 공공자료 8개 항목 조회, 주택 공시가격 미확인을 확인했다. 업무시설이라는 주용도를 빈집 자격으로 해석하지 않도록 안내한다. 모바일에서 필수 입력, 키보드 확인, 선택 변경, 잘못된 주소와 일반 안내 진입을 확인했다. URL에 주소가 없고 처음 조회에는 연락처 입력이나 DB 기록이 없음을 코드와 화면에서 확인했다. 고정 이미지 기준의 시각 회귀 비교와 Core Web Vitals 측정, 전체 접근성 인증은 수행하지 않았다.
