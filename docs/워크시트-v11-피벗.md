| **원인** | ① 자료가 기관별로 흩어져 있다 (공부·등기·세무·조례)<br>② 확인된 사실과 기억이 구분되지 않는다<br>③ **그 자산에 돈을 벌 이유가 있는 주체가 없어 아무도 정리해 주지 않는다** (W7) |

## ⚠️ 이 시트에서 나온 반론

프레이밍 ②(확인목록형)는 **영향을 사용자에게 전가한다.**

```
"확인할 일 12건"  →  가치가 아니라 숙제
```

PRD v0.1 스스로 **실제 행동전환 목표를 10~20%**로 잡았다.
**80~90%가 아무것도 안 할 것을 이미 예상하고 있다**는 뜻이고,
그렇다면 목록의 대부분은 영원히 미확인으로 남는다.

사람이 실제로 움직이는 것은 **마감·금액·타인의 요구** 셋 중 하나다.
*"도로접면을 확인하세요"*는 셋 다 아니다. **E5·E6는 그중 금액에 해당한다.**

**▶ 기획서 1번 — 고객 문제**

> 멀리 있는 땅·집의 상태를 확인하지 못해 **받을 수 있는 제도를 놓치고
> 처분·활용 결정이 미뤄진다.** 자료가 흩어져 있기도 하지만, 근본 원인은
> **그 자산에서 돈을 벌 주체가 없어 아무도 정리해 주지 않는다**는 것이다.

# W3 · 문제 쪼개기 (MECE)

**소유주가 아는 것 / 우리가 아는 것**으로 자른다. 이 축이 "몰랐던 정보"를 직접 설명한다.

| 영역 | 소유주가 아나 | 우리가 아나 | 교집합 가치 |
|---|---|---|---|
| 지목·면적·도로접면 | **안다** (수십 년 보유) | 안다 | ✕ 없음 |
| 건물 나이·구조 | 대충 안다 | 안다 | △ 낮음 |
| 등기 상태 | **안다** (본인 일) | **모른다** (공개 API 없음) | ✕ 역방향 |
| **세금·감면·특례** | **모른다** | **안다** (E5·E6) | **◎ 가장 큼** |
| **규제·용도 제약** | **모른다** | 안다 | **○ 큼** |
| 주변 시세 | 모른다 | **모른다** (어댑터 미구현) | **× 양쪽 다 모름** |

## 결론 셋

1. **"몰랐던 정보"는 세금과 규제 두 칸에만 있다.** 나머지는 사용자가 이미 안다.
2. **주변 시세는 양쪽 다 모르는 유일한 칸** → 어댑터를 붙였을 때 값이 가장 크다.
3. PRD v0.1 §8 룰 테이블이 **"지목이 전·답·과수원"부터 시작**한다 — 이 표에 따르면 **가장 가치 없는 칸**이다.

**▶ 기획서 3번 — 문제 쪼개기**

> 소유주가 모르는 것은 **세금·제도와 규제** 두 칸에 몰려 있다. 지목·면적·도로·
> 건물 나이는 이미 알고 있어 정보가 되지 않는다.
> **주변 시세는 양쪽 다 모르는 유일한 칸**이라 확보 시 가치가 가장 크다.

# W4 · 페르소나 / 타겟 세그먼트

**소유 개수가 아니라 「거리」로 자른다.**

## 대상이다

> **자산 소재지에 살지 않으면서, 시세가 형성되지 않는 부동산을 가진 개인.**
> 상속 시골집 · 빈집 · 세컨드하우스 · 농지 · 지방 토지.

거리로 자르는 이유 — 아파트 두 채 가진 사람은 이 문제와 무관하고,
반대로 **시골집 한 채만 상속받은 사람이 완벽한 고객**이다.
소유 개수 기준 세그먼테이션은 두 경우를 모두 틀리게 분류한다.

## 대상이 아니다

```
✕  아파트·연립·빌라 소유자       시세가 있고 은행이 이미 다룬다 (E3)
✕  거주 중인 자기 집만 가진 사람   거리 문제가 없다
✕  매입을 검토 중인 사람          보유가 아니라 거래. 다른 제품 (W15)
✕  법인·전업 투자자              이미 전문가를 쓴다
```

## 연령

**[가정]** 50~70대. 근거 없음. 첫 인터뷰에서 확인한다.
자녀(30~40대)가 실사용자인지도 **[미확인]** — 실제 관리 주체를 인터뷰에서 기록한다.

**▶ 기획서 4번 — 페르소나**

> **자산 소재지에 살지 않으면서 시세가 형성되지 않는 부동산을 가진 개인.**
> 소유 개수가 아니라 자산과 소유주 사이의 **물리적 거리**로 정의한다.

- **[미확인]** 위 비율이 「주택 수」 기준인지 「소유자 수」 기준인지 — KOSIS 원표 확인 필요.
- **v10의 "다주택자 237.7만"은 SAM으로 쓰지 않는다.** W4에서 폐기한 축이다.

**▶ 기획서 5번 — 시장 규모**

> TAM 개인 주택소유자 **1,597.6만 명** · SAM 타 시·도 소재 자산 보유 **≈ 217만 명**
> (통계청 주택소유통계, 시·도 동일 거주 86.4%의 여집합).

# W7 · 경쟁자

| 구분 | 서비스 | 하는 것 | 우리 타깃에 되나 |
|---|---|---|---|
| 은행 | 신한 부동산 자산관리 | 시세 + 대출 한도 + 금리 비교 | **✕ 등록 자체가 안 됨** — *"시세 조회가 가능한 주택"* 한정 |
| 은행 | KB부동산 | 아파트 시세·실거래·AI예측시세·빌라시세 | ✕ 시세 중심 |

| 프롭테크 | **밸류맵** | 실거래 + **"소유주 자산관리"** + 건축설계 + 사업성검토 | **⚠️ 가장 가까움 [미확인]** |
| 프롭테크 | 랜드북 | AI 적정가·사업성 분석 | ✕ 개발 의사결정용 |
| 프롭테크 | 부동산플래닛 | 전국 실거래가 + AI 추정가 | ✕ 거래 목적 |
| 정부 | 토지이음·정부24·세움터 | 원자료 열람 | △ **조회는 되지만 판단이 없다** |

## 🔴 이 시트에서 가장 중요한 두 줄

**① 밸류맵을 확인하지 않았다.**
*"소유주 자산관리"*를 명시적으로 표방한다. 다만 건축설계·사업성검토와 나란히
놓인 걸로 봐서 **"내 땅에 뭘 지으면 얼마 버나"** 쪽으로 보인다 — **[미확인]**.
**아버님 필지를 직접 넣어보기 전에는 W8을 확정할 수 없다.**

**② "왜 아무도 안 하는가"의 답이 둘이다.**

```
(a)  틈이 있다
(b)  돈이 안 돼서 안 한다
```

은행과 프롭테크가 **못 해서** 안 하는 게 아니다. 데이터도 자본도 압도적이다.
은행은 **담보가 안 잡히는 자산**을 볼 이유가 없고(그래서 시세 있는 주택만 받는다),
프롭테크는 **거래가 안 일어나는 자산**에서 수수료를 못 얻는다.

**그 이유는 우리에게도 그대로 적용된다.** W0 전제 4가 [미확인]인 이유다.

**▶ 기획서 7번 (1/2) — 경쟁 비교표**

> 은행은 **시세가 있는 주택만** 받고, 프롭테크는 **거래**에서 번다.
> 우리 타깃 자산은 시세도 거래도 없어 **어디에도 등록되지 않는다.**
> 단 밸류맵이 "소유주 자산관리"를 표방하고 있어 **직접 확인 전에는 공백을 단정할 수 없다 [미확인].**

# W8 · 포지셔닝

## 우리가 못 하는 것 — 먼저 쓴다

```
✕  시세를 못 낸다           비아파트 시세 산정 능력 없음

✕  법률 판단을 못 한다       처분 가능·통행권 확보를 결론짓지 않는다
```

## 그럼에도 왜 우리를 쓰는가

| 축 | 기존 | 우리 |
|---|---|---|
| 대상 자산 | 시세 있는 것 | **시세 없는 것** |
| 목적 | 거래·대출 | **보유 상태 파악** |
| 출력 | 얼마인가 | **무엇이 걸려 있고 얼마가 나가고 있나** |
| 수익원 | 거래 수수료·광고 | **전문가 연결** (법무사·세무사·시공사) **[미검증]** |

**수익 구조가 포지셔닝의 핵심이다.** 거래에서 벌려고 하는 순간 진 싸움이다.
거래가 아니라 **절차**(상속등기·보존등기·세무)에서 버는 구조여야
은행·프롭테크가 들어오지 않는 자리에 설 수 있다.

**▶ 기획서 7번 — 포지셔닝**

> **시세가 없어 아무도 다루지 않는 자산**을, 거래가 아니라 **보유 상태와 비용**의
> 관점에서 정리한다. 시세·등기 자동조회·전국·세액계산·법률판단은 하지 않는다.
> 수익은 거래 수수료가 아니라 **절차 전문가 연결**에서 낸다 **[미검증]**.

## 🔴 H1이 가장 위험하고, 지금 설계로는 검증되지 않는다

계획된 첫 인터뷰이가 **아버님 + 기존 빈집 인터뷰이**이고, **운영자가 대신 등록**한다.

```
신뢰 관계 있음  →  "낯선 서비스에 재산을 맡기겠는가"가 발동 안 함  →  H4 측정 불가
대리 등록      →  등록 완료율이 운영자 타이핑 성공률이 됨          →  H1 측정 왜곡
```

**편의표본 + 대리등록이 겹쳐서 가장 큰 채택 장벽이 검증에서 사라진다.**
**표본에 신뢰 관계 없는 2명을 반드시 넣고, 그 2명은 본인이 직접 주소를 입력해야 한다.**

**▶ 기획서 9번 — 가장 위험한 가정**

> **H1 — 소유주가 자기 자산 상태를 실제로 모른다.** 접촉 0명, 증거 0건.
> 그리고 현재 인터뷰 설계(가족·지인 + 운영자 대리등록)로는 **H1과 H4가 측정되지 않는다.**

**②를 버리는 게 아니라 ③ 아래에 넣는다.** 금액을 먼저 보여주고,

○   "이 집 재산세는 연 1.6만원입니다. 철거하시면 5년간 절반입니다.
     다만 그 감면을 받으려면 먼저 확인할 것이 있습니다."
```

## 사용자 플로우

```
주소 한 줄 입력
   ↓
필지 확정              fuzzy·복수 후보는 자동 확정하지 않음
   ↓
공부 수집 + 법령 대조     기존 rules.json + 확정된 세법
   ↓

# W13 · 성공 지표

**n=5에서는 비율을 못 잰다. 만장일치를 잰다.** 전부 사람 수로 쓴다.

| 지표 | 정의 | 판정 |
|---|---|---|
| **몰랐던 정보** | 진단서 보기 전 진술에 없었는데 진단서에 있던 항목. **운영자가 센다** | GO: 1건 이상이 **3명** / KILL: 0건이 **4명** |
| **행동** | 등기 열람·시청 문의·현장 확인·견적 중 실제 수행 | GO: 구체적 언급 **2명** |
| **자발적 WTP** | 묻지 않았는데 먼저 돈 이야기를 꺼냄 | GO: **1명** |
| **직접 등록** | 신뢰 관계 없는 2명이 **본인 손으로** 주소를 넣었는가 | KILL: **0명** |
| **"인터넷에 다 있다"** | 단순 조회 도구로 인식됨 | KILL: **4명** |

**자기보고를 쓰지 않는다.** *"몰랐던 정보 있었나요?"*라고 물으면 예의상 "네"가 나온다.
진단서를 보여주기 **전에** 아는 것을 먼저 받고 **차이를 관찰한다.**

## North Star (장기)

```
Managed Properties
  ① baseline 등록  ② 모니터링 활성  ③ 사용자가 떠나지 않은 상태로 갱신 1회 통과
```

**③을 "90일 내 데이터 갱신"으로 두면 안 된다** — cron이 돌면 전 자산이
조건을 만족해 지표가 100%로 고정된다. 부동산은 매달 뭘 할 필요가 없는 자산이라
**"안 떠난 것"이 유일한 유효 신호**다.

**▶ 기획서 13번 — 성공 지표**

> **몰랐던 정보 1건 이상이 5명 중 3명** (자기보고 아님, 운영자 관찰).
> 보조 — 구체적 행동 2명, 자발적 WTP 1명.
> **KILL — 몰랐던 정보 0건이 4명, 또는 직접 등록 0명.**
