# 빈집진단서 디자인 시스템

버전: **0.2** · 적용일: 2026-09-12  
상태: **주요 고객 화면과 관리자에 적용.** v0.1의 불일치 기록은 [최초 감사](design-audit-2026-09-12.md)에 보존한다. [적용·검증 기록](design-system-implementation-2026-09-12.md)

## 1. 시각적 원칙

따뜻한 종이색, 짙은 녹색, 왼쪽 정렬, 3D 집토끼를 유지한다. 작은 글씨로 정보를 압축하기보다 상세 내용을 펼쳐 보여준다.

- 고객이 읽는 순서: 비교할 결론 → 비용과 미확인 조건 → 다음 행동 → 출처.
- 확인됨·미확인·예시·조회 실패를 글로 구분한다. 색이나 캐릭터로 판정을 대신하지 않는다.
- 홈은 시작, 진단서는 비교, 관리자는 검토에 집중한다. 역할에 따른 폭·밀도 차이는 허용한다.
- 금액·자료·지원 자격을 미확인 상태에서 자동으로 확정하지 않는다. 디자인 변경으로 계산·공개·저장 동작을 바꾸지 않는다.

| 지원정보 `/resources` | 704px | 분류 이동·공식 정보 카드·신청 경로 |

## 3. 공통 색상

정의: [globals.css](../app/globals.css). 홈·진단서의 기존 변수와 Tailwind 색 이름은 이 토큰의 별칭으로 연결한다. 화면별 CSS에 별도의 HEX 팔레트를 추가하지 않는다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--brand-primary` | #285C49 | 주요 버튼·선택·브랜드 |
| `--brand-hover` | #194432 | 주요 버튼 hover |
| `--text-primary` | #263D34 | 제목·본문 |
| `--text-secondary` | #5C6D62 | 도움말·출처·placeholder |
| `--canvas` | #EEECE5 | 페이지 바깥 |
| `--surface` | #FFFEFA | 종이색 지면 |
| `--surface-raised` | #FFFFFF | 입력·카드 |
| `--surface-soft` | #EDF2E9 | 보조 영역·선택된 면 |
| `--border-subtle` | #DFE5DC | 장식 경계·구분선 |
| `--border-control` | #7B8A7E | 입력·선택지의 식별 경계 |
| `--status-unknown-text / surface / border` | #76572D / #F5EEE0 / #BBA784 | 미확인, 점선과 설명 |
| `--status-known-text / surface` | #36604B / #E9F1E5 | 근거를 확인한 항목 |
| `--status-error-text` | #A04023 | 오류, 수정 방법과 함께 |
| `--focus-ring` | #B7843B | 밝은 지면의 3px 포커스·offset 3px |

입력 경계를 `border-subtle`로 대체하지 않는다. 미확인 표식의 점선은 상태 표시이며 입력 식별 경계와 다른 역할이다. 기존 `--color-earth`는 오류색에 연결되므로 새 경고·미확인에는 해당 의미별 토큰을 사용한다.

placeholder는 이전 #7F877B에서 #5C6D62로 변경했다. 단색 대비는 [검증 기록](design-system-implementation-2026-09-12.md)을 참고한다. 새 inverse 화면을 만들면 별도의 전경·배경 조합을 정의해야 한다. 현재 신청 폼과 사진 선택기는 모두 밝은 테마다.

## 4. 타이포그래피

기본 서체: **Pretendard Variable → Pretendard → 운영체제 산세리프**. CDN이 제공하는 실제 가족 이름을 먼저 지정한다. 사용하지 않던 Noto Serif KR 로딩을 제거했고 기존 `font-serif`는 호환을 위해 같은 산세리프를 가리킨다.

Chrome의 실제 렌더링 폰트에서 `Pretendard Variable`, `isCustomFont: true`를 확인했다. CDN 접근이 불가능하면 fallback을 사용하므로 오프라인에서도 같은 모양을 보장한다는 의미는 아니다.

| 역할·토큰 | 데스크톱 / 620px 이하 | 기본 굵기 | 행간 |
| --- | --- | --- | --- |
| 페이지 제목 `--type-page` | 32 / 28px | 700 | 1.4 |
| 섹션 제목 `--type-section` | 24 / 22px | 700 | 1.5 |
| 카드 제목 `--type-card` | 20 / 18px | 700 | 1.5 |
| 본문 `--type-body` | 16 / 16px | 400 | 1.75 |
| 핵심 금액 `--type-amount` | 32 / 30px | 750 | 1.5 |
| 주요 버튼·입력 | 16 / 16px | 버튼 600 / 입력 400 | 1.5 |
| 도움말 `--type-help` | 14 / 14px | 400, 조작 600 | 1.7 전후 |
| 상태·메타 `--type-meta` | 12 / 12px | 500~600 | 1.6 |
| 브랜드 `--type-brand` | 20 / 18px | 750 | 1.5 |

토큰은 rem으로 정의하고 root 글자 크기를 축소하지 않는다. 제목은 대체로 -0.03em, 기본 본문은 -0.01em 자간을 사용한다. 강조·선택에는 600~650의 가변 굵기를 허용한다. 한국어 `keep-all`과 긴 주소의 `overflow-wrap:anywhere`를 함께 사용한다.

허용한 역할 차이:

- 관리자 목록·작업 패널의 H2는 카드 제목 규모 20/18px. 고객의 주요 H2는 24/22px.
- ‘금액 확인 필요’는 숫자 금액보다 작은 섹션 제목 규모. 미확인을 0원처럼 보여주지 않는다.
- 목차·출처·인쇄·복사·관리자 버튼은 도움말 규모 14px의 조밀한 변형.
- 12px은 보조 표식용이다. 지원 조건·오류·신청 동의·사진 도움말·고객 푸터는 14px 이상.
- 본문 16px은 서비스 기준이며 WCAG의 법정 최소 글자 크기라는 뜻이 아니다.

폴더 탭의 윗모서리, 알약형 목차, 원형 순서 번호, 집토끼의 광학적 보정은 별도 형태다. 기존 페이지 프레임의 20~42px 여백·표 안의 소간격 일부는 호환값으로 남아 있다. 새 컴포넌트에는 임의 px를 추가하지 않고 이 토큰을 사용한다. 모든 기존 간격 선언을 토큰으로 바꾼 상태는 아니다.

## 6. 공통 컴포넌트와 상태

구현: [ui.module.css](../app/ui.module.css), [home-ui.tsx](../app/home-ui.tsx). CSS Modules의 `composes`로 공유 스타일을 사용하며 링크·버튼·입력의 HTML 의미를 유지한다.

| 변형 | 규칙 | 적용 예 |
| --- | --- | --- |
| `primary` | 최소 56px, 16px, 녹색, 12px 모서리 | 조회·신청·진단 시작 |
| `secondary` | 최소 48px, 16px, 밝은 면·식별 경계 | 지원정보 전체 보기 |
| `compact` | 최소 44px, 14px, 8px 모서리 | 인쇄·관리자 보조 버튼 |
| 관리자 primary | 44px, 14px의 명시적 변형 | 처리 기록 저장 |
| `input` | 최소 54px, 16px, 12px 모서리 | 추가 신청·관리자 상세 |
| `choice` | 최소 48px, 카드 전체 label | 신청 라디오 |
| `known / unknown / neutral` | 12px, 공통 패딩·모서리·상태색 | 홈·진단서·지원 카드 |
| `Brand` | 아이콘 40px, 이름 20/18px | 홈·진단서·관리자 |
| `HomeLink` | `← 홈으로`, 높이 44px, 항상 `/` | 고객용 하위 화면 |

별도 형태가 필요한 홈 주소 입력·진단서 계산기·관리자 필터도 같은 폰트·경계·모서리 토큰을 따른다. 모든 입력을 단일 React 컴포넌트로 교체한 것은 아니다.

상태 규칙:

- 주요 버튼: 기본 → 진녹색 hover → 3px focus → 비활성·진행 문구. 상태 전환은 기본 150ms.
- 라디오: native 선택점과 카드의 배경·경계가 함께 바뀐다. 입력 원형은 20px, label 전체가 터치 영역이다.
- 오류: 색만 바꾸지 않고 설명을 남긴다. 추가 신청의 주소·전화·이메일·동의 오류는 입력과 `aria-describedby`로 연결한다.
- 사진: 선택 개수·준비 중·형식 오류·삭제를 표시한다. 접수와 분석 완료를 혼동하지 않는다.
- 금액: ‘설명용 가정값’은 숫자 가까이 표시한다. 빈칸은 미확인, 확인한 0은 0. 숫자 우측 정렬과 tabular-nums를 사용한다.
- 관리자 업무 상태는 집의 안전·권리 상태나 진단서 공개 여부와 별개다.
- 고객 명칭은 ‘진단서’, 공식 링크 페이지는 ‘빈집 지원·정보 모음’. 진단서 상단의 좁은 탐색 링크만 ‘지원·정보 모음’으로 줄여 쓴다.

## 7. 로고와 집토끼

| 자산 | 경로 | 적용 |
| --- | --- | --- |
| B안 3D 집 | `public/brand/binzip-house-logo-b-3d-v2.png` | 40×40 로고. 이미지 자체는 종이색 배경 |
| 집을 안은 집토끼 | `public/mascot/binzip-rabbit-v1.png` | 홈, 투명 배경 |
| 돋보기 집토끼 | `public/mascot/binzip-rabbit-report-transparent-v4.png` | 진단서·관리자, 투명 배경 |

사용자가 조정한 이미지 박스·transform은 유지했다.

- 홈: 180×220px, `translate(-10px,12px) scale(1.2)`.
- 홈 540px 이하: 130×188px, `translate(-10px,12px) scale(1.188)`; 360px 이하 110×174px.
- 진단서: 144×144px, `translate(-50px,54px) scale(1.65)`.
- 진단서 620px 이하: 104×120px, `scale(1.21)`; 인쇄 100×100px, transform 없음.
- 관리자: 88×104px, 작은 화면 65×82px.

문장·폰트가 변경되므로 주변 콘텐츠와의 절대 좌표는 달라질 수 있다. 실제 보이는 발 위치는 투명 여백을 포함한 이미지 박스의 끝과 다르다. 겹침 문제는 텍스트 배치를 먼저 조정한다.

## 8. 반응형·접근성·인쇄

- 고객용 제목·핵심 컴포넌트: 620px 전환. 홈 외곽·집토끼 배치: 540px, 작은 예외: 360px. 관리자 레이아웃: 768px.
- 진단서 헤더는 글자가 확대되어 공간이 부족하면 다음 줄로 이동한다. 비교·입력 카드와 관리자 상세는 작은 화면에서 한 열로 바뀐다.
- 명시적인 라벨, native 라디오·details·button, 키보드 포커스를 유지한다. 감소된 모션 설정에서는 불필요한 전환을 줄인다.
- 인쇄는 A4·14mm. 도움말·메타 토큰도 1rem으로 올려 본문·표·출처를 최소 12pt로 출력한다.
- 인쇄 시 선택기·입력기·복사·홈 귀환·페이지 내부 이동·신청 CTA를 숨긴다. 선택한 행동과 출처는 남긴다.
- 기존 beforeprint/afterprint 동작으로 상세 근거를 펼쳤다가 화면 상태를 복원한다. 근거 묶음·비교 카드·행동 단계의 페이지 분할을 억제한다. 긴 지원 카드는 페이지를 나눌 수 있으며 개별 지원 조건은 함께 유지한다. 한 페이지보다 긴 실제 내용은 분할될 수 있다.

검증 기준과 실제 결과는 [적용·검증 기록](design-system-implementation-2026-09-12.md)에 구분한다. 반응형 Chrome 검사는 실제 iPhone/Safari 검사나 전체 접근성 인증을 대신하지 않는다.

## 9. 유지 방법

새 구성은 역할·크기·선택/진행/오류/포커스·모바일·인쇄를 함께 확인한다. 공통값은 `globals.css` 또는 `ui.module.css`에서 수정하고, 페이지 전용 예외는 이유를 기록한다. 안전·세금·권리·지원 자격처럼 확인이 필요한 내용을 디자인 개선과 함께 확정형 문구로 바꾸지 않는다.
