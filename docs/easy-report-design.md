# 큰 글씨 진단서 시안

> 후속 리뉴얼: 두 예시 주소 모두 큰 글씨 기반의 ‘집 정보 → 철거 준비 → 상담 → 진행 확인’ 화면으로 통일했다. 현재 구성은 [철거 진단서 흐름](demolition-report-flow.md)을 따른다. 아래 내용은 초기 시안의 설계·검증 기록이다.

작성일: 2026-09-12 · 상태: 별도 예시 페이지, 기본 고객 진단서로 전환하지 않음

- 새 시안: `/example-report/easy`
- 기존 예시: `/example-report` — 상단에 시안 링크를 추가하고 예시 안내 기준을 동일하게 적용
- 실제 고객 `/report/[id]`, 신청 흐름과 진단 로직은 이번 변경 범위에 포함하지 않음

## 목적과 구성

사용자는 50·60대도 편하게 읽을 수 있도록 큰 글씨와 단순한 화면 구성을 요청했고, ‘한 페이지에서 차근차근 읽기’를 선택했다. 기존 색·서체·집토끼를 유지하면서 숫자·버튼·근거 카드가 동시에 경쟁하는 밀도를 줄인다. 연령만으로 독해 능력을 가정하거나 사용성이 검증됐다고 주장하지 않는다.

1. 최상단에 예시 데이터임을 한 번 안내하고 짧은 목차를 제공한다. 본문에는 가정값·설명용 안내를 반복하지 않는다.
2. **돈 비교:** 그대로 팔기 / 철거 후 팔기의 남는 돈을 같은 비중으로 보여준다. 입력·계산 내역은 펼쳐 본다. 어느 쪽도 추천으로 강조하지 않는다.
3. **다음 할 일:** 고민 중 / 팔기 / 철거하기 / 당분간 두기 중 선택하면 세 가지 행동을 보여준다. 방법·문의할 질문·연결 링크는 각 단계에서 펼친다.
4. **지원 확인:** 사업별 조건·기관 연락처·근거를 펼쳐 본다. 철거 견적의 포함 범위도 이곳에서 확인한다.
5. **집의 기록:** 대보리 126-6 단일 사례의 건물 정보와 등기부·건축물대장 요약을 펼쳐 본다. 서류 확인과 미진행 현장 확인을 구분한다.
6. 내 집 주소로 시작하기와 인쇄·전화 문의를 마지막에 둔다.

첫 화면에 총비용의 모든 항목, 여러 경고 배지, 모든 공식 링크를 한꺼번에 나열하지 않는다. 큰 글씨를 유지하므로 페이지 길이 자체가 짧아진다는 보장은 없다. 목차로 원하는 구간에 이동할 수 있다.

## 시각 기준

전용 CSS Module의 루트 안에서만 글자 토큰을 바꾼다. 기존 진단서의 본문 16px은 유지한다.

| 역할 | 데스크톱 | 620px 이하 |
| --- | --- | --- |
| 본문 | 20px / 행간 1.8 | 20px / 행간 1.8 |
| 보조 설명·주요 조작 | 18px | 18px |
| 출처·예시 표기·상태 | 최소 16px | 최소 16px |
| 페이지 제목 | 40px | 32px |
| 구간 제목 | 30px | 26px |
| 핵심 금액 | 42px | 38px |
| 선택 영역 | 최소 높이 60px | 최소 높이 60px |

960px 지면, 데스크톱 안쪽 48px / 모바일 20px 여백. 데스크톱의 금액 비교와 입력은 두 열, 모바일은 한 열이다. 선택지는 760px 이하에서 두 열, 목차는 620px 이하에서 두 열로 흐른다. 고정 높이로 문장을 자르지 않는다. 기존 팔레트와 간격·모서리 토큰을 재사용한다.

집토끼는 텍스트와 다른 그리드 칸에 두며, 본문 위에 겹치지 않는다. 예시의 장식 이미지이므로 빈 alt를 사용한다. 새로운 이미지 편집은 하지 않았다.

## 데이터와 상호작용

- `src/disposal.ts`의 기존 계산 함수·검증·가정값을 재사용한다. 초기 2,200만 원 / 2,250만 원은 설명용 계산이며 시세나 견적이 아니다.
- 최상단에 지정 주소를 사용한 예시이며 등기·건축물 정보와 금액은 가상 데이터라는 안내를 한 번 표시한다. 금액 카드·펼침 설명·초기화 버튼에는 반복하지 않는다. 이 안내는 인쇄에도 남긴다.
- 빈 입력은 미확인, 잘못된 입력은 오류, 음수 결과는 ‘추가로 필요한 돈’으로 표시한다. 확인되지 않은 지원금을 자동 차감하지 않는다.
- 이 시안의 계산 입력은 컴포넌트 메모리에만 있고 새로고침으로 초기화된다. 저장·전송하지 않는다.
- 기존 `DECISION_ACTIONS`, 공식 사이트 목록, `buildSupports`를 재사용한다. 예시의 다음 행동은 준비된 서류로 담보 상환·매도 상담을 진행하는 내용으로 조정했다. 선택한 방향은 진단 결과나 지원 자격을 바꾸지 않는다.
- 두 예시가 쓰는 근거 문구를 `src/example-report-data.ts`로 추출했다. 실제 고객 보고서에서는 이 예시 데이터를 사용하지 않는다.
- 단일 사례의 가상 등기·건축물 정보와 표시 범위는 [예시 사례 데이터](example-case-data.md)를 따른다. 원본 증명서를 모방하지 않고 진단서 안에서 서류의 항목별 요약을 보여준다.
- 지원 정보는 기존에 정리한 자료를 표시한다. 이번 UI 작업에서 접수·예산이나 법령을 새로 검증한 것은 아니다. 기존 출처·확인일·미확인 설명을 유지한다.

## 접근성과 인쇄

native radio·fieldset·details·summary·link를 사용한다. 선택과 입력에 이름을 붙이고, 입력 오류를 해당 필드와 연결한다. 키보드 포커스, 본문 바로가기, 계산 결과와 선택 안내의 변경 알림을 제공한다. 상태는 색만으로 구분하지 않는다.

공용 `ReportTools`의 인쇄 전 펼치기 / 인쇄 후 복원 동작을 재사용한다. 인쇄에는 금액별 계산 내역을 별도 표시하며, 입력 조작·선택기·시안 전환·신청 버튼을 숨긴다. 공적 지원과 근거 설명은 인쇄에 남긴다.

## 확인 기록

- Chrome 반응형 320 / 375 / 390 / 768 / 1440px: 기본 및 모든 상세 펼침 상태에서 가로 넘침 없음.
- Chrome 375px에서 루트 글자 200%: 모든 상세를 펼친 상태에서 페이지 가로 넘침 없음. 실제 브라우저 줌·보조기기 전체 검증을 뜻하지 않는다.
- 계산 예시, 빈 값, 잘못된 값, 음수, 비우기·초기화, 네 가지 선택별 세 단계 안내, 지원 위치 이동·연락처 펼침 확인.
- 키보드 Enter로 상세 열기·닫기 확인. 인쇄 상세 펼치기와 화면 상태 복원 확인.
- 기존 진단서 16px 유지 및 시안 왕복 링크·홈 주소 입력으로 이동 확인.
- 기존 테스트 33개, TypeScript 검사, 배포용 빌드 통과. 빌드 후 로컬 응답 200과 모바일 선택 안내도 확인했다. PDF 첫 페이지를 렌더링해 금액·계산 내역 배치를 확인했다.
- 결과와 화면, 브라우저 검사 스크립트: `output/easy-report-2026-09-12/` (Git 제외).

실제 50·60대 사용자를 대상으로 읽기·이해·조작을 확인한 결과는 아직 없다. 후속 사용성 확인에서는 ‘남는 돈 찾기’, ‘철거 지원 문의처 찾기’, ‘현재 미확인인 항목 말하기’의 완료 여부·시간·도움을 요청한 횟수를 관찰한다. 시각 변경만으로 수치 개선을 주장하지 않는다.

실제 고객 보고서에 적용하기 전에는 이 시안의 고정 예시 문구를 보고서 데이터에 연결하고, 조회 실패·선행 조건·진행 제한을 상단에 유지하는 별도 검증이 필요하다.
