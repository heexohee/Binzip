# 주소 확인 → 상세 정보 입력 (2026-09-12)

## 사용자 흐름

1. 메인 첫 소개 영역에 통합된 `/#address-search` 폼에서 주소만 입력한다. 폼은 소개·집토끼 아래 전체 너비로 표시하며, 폼 위에 ‘내 빈집 확인 / 진단서 예시’ 탭 모양 링크를 둔다. 별도 중복 신청 영역은 없다. 고민·연락처를 먼저 요구하지 않는다.
2. 같은 화면에서 지번·도로명주소, VWorld 위성·항공사진, 주소 조회 좌표 표시점을 보여준다. 모든 조회 결과는 사용자가 확인하며 유사 주소에는 별도 주의 문구가 있다.
3. `이 집이 맞아요 · 상세 정보 입력`을 누르면 `/apply`로 이동한다. 입력 주소·조회 주소·필지번호·일치 품질·지도 좌표는 React context 메모리로 전달한다.
4. 상세 폼의 주소와 조회 결과는 채워져 있고 지도는 펼쳐 다시 볼 수 있다. 집 상태·사진·취득 경위·소유관계·고민·연락처·동의를 입력하고 기존 신청 액션으로 접수한다.

주소를 고치면 기존 확인 결과와 지도는 즉시 무효화된다. 먼저 시작한 요청이 늦게 도착해 최신 주소를 덮어쓰지 않는다. 이전 `/diagnose` 진입은 메인 주소 입력 단계로 이동한다. 기존 즉시 진단 조회 모듈은 보존하되 현재 시작 경로에서는 사용하지 않는다. 홈 FAQ·이용 단계·개인정보 설명도 현재 흐름으로 맞췄다.

## 지도와 실패 처리

- `api/address`: 기존 Juso/Kakao 주소 확인과 VWorld 지오코딩을 사용한다. 결과가 없을 때와 조회 연결 실패를 구분한다.
- `api/map`: VWorld PHOTO 정적 영상 프록시를 재사용한다. API 키는 서버에만 둔다. 실패 원문·키를 브라우저나 신규 오류 로그로 반환하지 않는다.
- 표시점은 조회 좌표다. 실제 건물 경계·빈집 여부·건물 상태·안전성을 확정하지 않는다. 사진은 촬영 시점과 현재 모습이 다를 수 있다.
- 지도 좌표가 없거나 영상 호출이 실패하면 안내를 표시한다. 주소가 맞으면 사용자가 다음 단계로 갈 수 있고 영상 오류는 재시도할 수 있다.
- 주소 확인 중 새 입력을 시작하면 이전 요청을 취소하고 재시도할 수 있다. 클라이언트 전체 조회는 20초, 지오코딩은 5초, 위성 영상 조회는 10초 상한이다.

## 정보와 저장

페이지 이동 URL, localStorage, sessionStorage에 주소를 넣지 않는다. 새로고침하면 메모리 전달값은 초기화되고 직접 열린 상세 폼에서 주소를 다시 입력할 수 있다. 메인 확인만으로는 신청 DB 기록이나 연락처 수집·메일 발송이 없다. 상세 폼 제출·사진 저장·관리자 승인 방식은 기존 방식이다.
