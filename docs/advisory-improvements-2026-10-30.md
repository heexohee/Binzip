## 저장·운영
- /interest: Supabase RPC 성공으로 접수번호를 받은 뒤에만 성공 표시. 설정/테이블 미적용·통신 실패는 실패 안내. 실패해도 입력값 유지.
- /admin/interests: 관리자 인증 필수. 최신 유효 500건, 방향/가격/필요관리/연락처/유입 확인, 연락 상태 저장.
- 동의는 이번 신청 관련 연락만 포함. 업체 제공·광고 발송 동의로 재사용 금지.
- DB RLS + anon/authenticated 차단. 서버 service_role만 사용.
- 제출 UUID로 재시도 중복 방지, 동일 전화번호 시간당 3회 제한. 봇 방어가 완전한 것은 아니므로 운영량에 따라 강화 필요.
- 만료 레코드는 조회에서 제외하며 pg_cron으로 시간 단위 삭제. 진단 신청의 기존 purge_expired도 예약.
- 진단 신청은 이메일 알림만 성공한 경우 완료 처리하지 않고 DB 저장을 요구. 이메일은 DB 저장 후 운영자 알림용.

## 배포 전 필요한 작업
1. Supabase SQL Editor에서 `supabase/care-interests.sql` 실행. 신규 테이블·RPC·이메일 nullable·Cron 설정 포함. pg_cron 활성화 권한이 없으면 오류를 확인하고 Supabase Cron을 활성화한 뒤 재실행. 기존 진단 schema.sql의 purge_expired 함수가 있어야 한다.
2. Vercel의 기존 SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY / ADMIN_TOKEN 사용. 키를 클라이언트에 노출하지 않음.
3. 카카오톡 채널이 준비됐다면 선택적으로 KAKAO_CHANNEL_URL=https://pf.kakao.com/... 설정.
4. 개선 브랜치 리뷰·배포 후 본인 연락처로 실제 등록 1건 → 관리자 목록 및 연락 상태 저장 확인. 이 단계는 아직 미확인.
5. 관리자에서 DB 접수 건을 확인하고 실제 안내는 운영자가 수행. 관심 등록에는 자동 SMS·메일 발송 없음.
6. Supabase Cron 실행 이력에서 삭제 작업 성공 확인. 삭제 요청은 운영자가 대상 care_interests 행을 삭제하며 별도 사본도 함께 관리.

## 마케팅과 증거
- 관리 캠페인 링크: /interest?utm_source=instagram
- 홈페이지 유입도 ?utm_source=instagram 사용 시 같은 탭의 관심 등록까지 출처 유지.
- 가격 선택은 실제 결제 증거가 아니다. 관심 등록 수 → 연락 성공 → 실제 업무 요청 → 가격 제시 후 유료 전환을 따로 기록한다.
- 확정 서비스 가격·제공 지역·방문 빈도를 광고로 약속하지 않는다.
- 방문자 대비 전환율은 별도 방문 분석 도구가 없으므로 여기서 산출하지 않는다.
- 구조안전·세무·법률 전문 판단을 제공한다는 의미로 광고하지 않는다.
