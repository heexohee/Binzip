# 전문가 상담 화면

- /example-report#consultation: 진단서 마지막 04 섹션에서 고객 상담 요청. 업무 선택, 전문가 확인, 선택 문의, 공유 동의 후 상담별 고객 화면으로 이동.
- /connect: 별도 요청 화면 없이 위 진단서 섹션으로 리디렉션.
- /connect/[id]: 고객의 견적 검토, 계약 확인 기록, 결과 확인, 전문가와 상담.
- /experts: 전문가 상담 업무 목록과 상태 필터.
- /experts/[id]: 상담 수락, 견적·조건 등록, 답변과 진행 기록, 완료 확인 요청.

## 담당자 대화와 방문 일정

고객과 담당자는 같은 상담의 별도 화면에서 말풍선으로 대화한다. 접수·상태 변경은 `빈집진단서 · 자동 안내`, 직접 입력한 답변은 업체명과 `담당자`로 구분한다. 고객은 요청 직후부터 문의를 남길 수 있고, 담당자는 상담 수락 후 답변한다.

고객은 채팅 또는 전화 상담을 선택한다. 전화 상담은 번호와 연락 가능한 시간을 저장한다. 담당자는 향후 90일 중 방문 후보 2~3개, 방문비와 준비사항을 보낸다. 고객이 방문비 안내를 확인하고 날짜를 선택한 다음 담당자가 최종 확정한다. 다른 날짜 요청 및 새 제안도 지원한다. 날짜는 한국 시간 기준이며 지난 시간, 중복 후보, 오래된 제안에 대한 응답을 거부한다. 조율 중인 방문이 있으면 확정 후 견적을 보낼 수 있다.

진단서 마지막 섹션은 상담 요청에 집중하며 기존 상담 목록을 표시하지 않는다. 견적, 계약 확인 기록, 완료 확인은 상담방에 함께 표시한다.

같은 상담의 데이터는 브라우저 localStorage에 저장한다. 같은 출처의 탭끼리 storage 이벤트로 변경 사항을 공유하고 새로고침 후 복원한다. Web Locks 사용 가능한 브라우저에서는 상담별 쓰기를 직렬화한다. 초기 문의는 선택이며 상담 요청 시 함께 저장된다. 상태 변경은 역할 및 선행 단계를 검증한다.

현재 자료와 업체는 기존 화면용 데이터다. 실제 전송, 업체 가입·검증, 사용자 인증, 서버 저장, 별도 기기 동기화, 계약 체결, 결제는 구현하지 않았다. 전문가 목록의 접근 분리는 화면상의 역할 구분이며 보안 경계가 아니다. 운영 배포 전 서버 인증·권한 및 동의 기반 데이터 전달을 구현해야 한다. 화면의 계약 확인은 별도 계약 확인 기록이며 전자계약이 아니다.

검증: scripts/consultations.test.ts에서 철거·매도 정상 흐름, 역할·단계 위반, 빈 문의 허용, 잘못된 견적·내용 거부를 확인한다.

브라우저 검증: 철거 요청 → 별도 전문가 화면 수락 → 답변·견적의 고객 탭 반영 → 고객 계약 확인 → 전문가 완료 요청 → 고객 최종 완료 → 새로고침 복원을 확인했다. 문의 없이 매도 상담 요청도 확인했다. 프로덕션 빌드 및 상태 전이 테스트 통과. 모바일 뷰포트 오버라이드는 실제 탭에 적용되지 않아 이번 변경의 모바일 검증은 미완료다.

2026-09-15 대화형 상담 검증: 고객 요청 → 전화 연락 방법 저장 → 담당자 수락·직접 답변 → 방문 후보와 비용 제안 → 비용 확인 전 선택 비활성 → 고객 날짜 선택 → 담당자 확정 → 고객 새로고침 복원 → 견적 전달의 탭 간 반영을 확인했다. 직접 답변과 자동 안내의 구분을 화면에서 확인했다. 날짜·시간 선택 컨트롤은 브라우저 호환성을 위해 각각의 선택 목록으로 구현했다. 확장한 상태 전이 테스트와 프로덕션 빌드도 통과했다. 이 흐름 역시 같은 브라우저의 로컬 저장을 사용하며 실제 연락 전송·기기 간 공유는 지원하지 않는다.
