# 관리자 신청 관리 — 2026-09-12

- `/admin-preview`: 가상 신청 6건. 검색, 상태·사진 필터, 상세, 처리 상태·내부 메모를 브라우저 메모리에서 체험. 실제 데이터베이스/사진/고객 연락처를 읽거나 쓰지 않으며 새로고침하면 초기화된다.
- `/admin/login`: 운영자 접근 키 로그인. URL의 `?k=` 방식은 제거했다. 쿠키는 httpOnly, sameSite=lax, `/admin` 경로, 12시간이며 배포 환경은 secure로 설정한다. localhost/127.0.0.1의 로컬 HTTP는 예외다.
- `/admin`: 동의하고 추가 확인을 신청한 건만 표시. 즉시 진단 조회는 저장하지 않는다. 최근 미만료 100건 기준 건수이며 누적 방문·전체 신청 통계가 아니다. 데이터 연결 실패와 신청 0건을 구분한다.
- `/admin/[id]`: 고객 입력·사진·자동 초안 확인, 처리 상태와 내부 메모, 기존 공개 진단서 검토. 내부 상태의 완료는 거래/철거 완료나 진단서 발송을 의미하지 않는다. `issued`는 공개 승인이지 전달 완료가 아니다.

## 운영 연결

현재 로컬 `.env.local`에는 공공자료 조회 설정만 있다. 실제 운영에는 `ADMIN_TOKEN`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 및 기존 신청/사진 스키마가 필요하다. 원격 키 복사나 원격 DB 변경은 이번 작업에서 하지 않는다.

기존 DB에는 `supabase/migrations/20260912_admin_workflow.sql`을 적용한다. 추가 컬럼은 `review_status`, `internal_note`, `review_updated_at`이며 기존 RLS·만료 파기가 그대로 적용된다. 새 DB는 `supabase/schema.sql`과 사진 마이그레이션을 사용한다. 기존 데이터에서 컬럼이 없으면 신청 조회는 제공하되 새 상태·메모 저장은 막고 설정 안내를 보여준다.

## 접근과 공개 범위

- Middleware 외에도 각 관리자 서버 액션·상세·사진 경로에서 인증을 확인한다. 보고서 수정은 UUID·신청 소속·신청 만료 여부를 확인한다.
- 공개된 진단서의 고객용 메모는 승인 취소 후에만 수정한다. 실패한 초안은 승인할 수 없다. 내부 메모는 별도 필드로 유지되며 고객 보고서 모델에 전달되지 않는다.
- 로그인 오류는 키를 출력하지 않는다. 15분당 10회로 제한하며 IP는 일시적인 salted hash로만 메모리에 보관한다. 제한은 인스턴스 단위이고, 배포 환경에서 신뢰할 수 있는 프록시 IP 설정과 여러 인스턴스 간 전역 제한은 별도 확인이 필요하다.
- 대량 내보내기, 고객 메시지 발송, 계정별 권한, 실제 현장/등기 판단 방식 변경은 포함하지 않는다.
