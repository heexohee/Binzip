> 2026-09-05 작성 · 대상 기간 **9/5(토) ~ 9/18(금), 13일**
> 1차 설계 → `docs/설계.md` (랜딩·폼·판정 파이프라인. **구현 완료·배포됨**)
> 이 문서는 그 다음 증분만 다룬다 — 결과 이력 저장, 진단서 뷰, 행동 경로, 전달.

---

## 1. 왜 이걸 하는가

현재 서비스는 **입력만 있고 결과가 없다.** 신청이 들어오면 운영자에게 메일 한 통이 갈 뿐,
판정 결과가 어디에도 남지 않고 소유주가 볼 화면도 없다.

앱 유형으로 보면 우리는 **흐름–결과형**인데 세 열 중 두 칸이 비어 있다.

| 열 | 정의 | 1차 이후 상태 |
|---|---|---|
| 화면 | 입력 · 진행 · 결과 | 입력 ✅ / 진행 ❌ / 결과 ❌ |
| 로직 | 판정 규칙, AI 호출 | 판정 규칙 ✅ / AI 호출 ❌ (의도적) |
| 데이터 | 입력값, 결과 이력 | 입력값 ✅ / **결과 이력 ❌** |

이 문서가 채우는 것은 **결과 이력**과 **결과 화면**이다.

### 가치사슬에서의 위치

```
상속·빈집 발생 → 뭘 해야 할지 모름 → [자산 진단] → 행동 결정 → 실행
                                      ↑ 우리        ↑ 이 문서   ↑ 파트너
```

우리 마지막 단계가 임대관리·리모델링 사업자의 첫 단계와 맞물린다.
유휴/블랭크는 경쟁자이면서 **downstream partner 후보**다.
다만 연결은 이번 범위가 아니다 (§5).

## 3. 입력 — 폼 9칸

```
1  빈집 주소                    필수   ← 검색창 + 돋보기 (1차 완료)
2  집 상태 한 줄                선택
3  이 집은 어떻게 갖게 되셨나요?  선택   ★신규
     상속 / 매입 / 가족 소유 / 기타
4  현재 소유관계를 알고 계신가요? 선택   ★기존 칸 교체
     단독 / 공동 / 상속 정리 중 / 잘 모름
5  가장 걱정되는 것은?           선택   ★신규
     세금 / 등기·상속 / 건물 상태 / 관리 / 매각 가능성 / 활용 방법 / 잘 모르겠음
6  진단서를 어디로 보내드릴까요?  필수
7  전화번호                      필수
7-1 이메일 주소                  6번에서 이메일을 고른 경우 필수
9  희망 소요                     선택   ★신규
8  개인정보 동의                 필수   ← 법적 확인이라 제출 버튼 바로 앞에 둔다
```

**필수는 넷이다 — 주소 · 받을 방법 · 전화번호 · 동의.**
초안에서는 셋이었으나 구현하면서 둘이 바뀌었다.

- **받을 방법을 필수로 올렸다.** 어디로 보낼지 모르면 진단서가 도달하지 못한다.
  도달이 이 서비스의 핵심 지표다.
- **연락처를 전화번호와 이메일로 나눴다.** 전화번호는 항상 받는다 —
  진단서 발송이 실패해도 닿을 수단이 하나는 있어야 한다.
  이메일은 6번에서 이메일을 고른 경우에만 나타나고 그때 필수다.

신규 3개(취득 경위·소유관계·걱정거리)와 희망 소요는 모두 선택이므로
폼이 길어져도 이탈 지점이 늘지 않는다. 목표는 2주 3건이고 타겟은 40~70대 모바일이다.

### 4번을 교체하는 이유

기존 칸(`이 집은 누구 집인가요?`)은 **신청자와 집의 관계**를 묻는다.
새 칸은 **등기상 소유 형태**를 묻는다.
①칸(미등기·공동상속 미합의) 판정에는 후자가 직접적이다 —
"가족 소유입니다"로는 단독인지 공동인지 알 수 없다.
두 질문을 다 두면 40~70대에게 혼란스러우므로 교체한다.

### 9번 문항 (확정 문구)

> **진단서를 언제까지 받고 싶으신가요?**
> ☐ 빠를수록 좋습니다 — 서류로 확인되는 것만 (1~2일 안에)
> ☐ 정확한 게 좋습니다 — 집으로 담당자가 직접 가서 확인한 뒤 (일주일 안에)
> ☐ 상관없습니다

"임장"은 소유주가 쓰지 않는 말이라 행동으로 풀었다.
실제 제공은 임장 포함 하나이므로 **완료 화면 문구는 "최대 1주일"을 유지**한다.
이 칸은 제공 조건을 바꾸지 않고 수요만 측정한다.

## 4. 결과 — 3등급과 6경로

### 두 축을 섞지 않는다

| | 답하는 질문 | 위치 |
|---|---|---|
| **3등급** | 지금 거래가 막혔는가 | 진단서 1페이지 |
| **6경로** | 그래서 무엇을 할 수 있는가 | 진단서 2페이지 |

3등급이 경로 가용성을 제한한다. 그러지 않으면
"지금은 불가"인데 "매각"이 위에 오는 모순이 난다.

| 판정 | 열리는 경로 |
|---|---|
| 지금 처분 가능 | 매각 · 임대 활용 · 수리 후 사용 · 당분간 보유 |
| 조건부 | 위와 같되 각 경로에 `먼저 ○○을 하시면` 조건이 붙는다 |
| 지금은 불가 | **권리관계 선행** 또는 **철거 검토**만 |

### 6경로

| 경로 | 이어지는 실행 | 색 |
|---|---|---|
| 권리관계 선행 | 전문가 확인 (법무사·세무사) | 기본 |
| 매각 | 공인중개사무소 | `deep` |
| 임대 활용 | 임대관리 | `deep` |
| 수리 후 사용 | 리모델링 | `deep` |
| 당분간 보유 | 관리 | 기본 |
| 철거 검토 | 철거 | `earth` |

`earth`는 페이지 전체 2곳 이하라는 디자인가이드 §2 규칙을 지킨다 — 철거 항목에만 쓴다.

### 정렬 규칙

```
1순위   ①칸(등기·공동상속)이 blocked 또는 unknown → 권리관계 선행 고정
        └ 등기가 안 풀리면 매각도 임대도 못 한다. 예외 없음
2순위   폼 5번(가장 걱정되는 것)이 지목한 경로
3순위   판정상 가능한 나머지 경로
맨 아래  지금은 안 되는 경로 — 점선 + 왜 안 되는지
```

**안 되는 경로도 지우지 않고 보여준다.** 진단서의
"확인하지 못한 것을 확인한 것처럼 적지 않는다"와 같은 원칙이다.
소유주는 "왜 이건 안 되지"를 알아야 다음을 판단한다.

### 폼 5번 → 경로 매핑

| 걱정 | 앞세울 경로 |
|---|---|
| 세금 | 전문가 확인 (세무사) |
| 등기·상속 | 권리관계 선행 |
| 건물 상태 | 수리 후 사용 |
| 관리 | 당분간 보유 |
| 매각 가능성 | 매각 |
| 활용 방법 | 임대 활용 |
| 잘 모르겠음 | 판정 결과 순서대로 |

같은 판정이라도 사람마다 먼저 보고 싶은 것이 다르다.
유휴 폼에 없는 칸이고, W8의 "판정 중립성"이 실제로 작동하는 지점이다.

### 진단서 2페이지 구조

핸드오프 §2의 `이 집으로 할 수 있는 것`(매각·임대전환·철거 3개)을 6개로 넓힌다.
레이아웃(`grid 100px 1fr`, 제목 Serif 600 18px)은 그대로 쓴다.

## 5. 법적 제약

`docs/설계.md` §9의 제약을 모두 승계하고 아래를 더한다.

| 행위 | MVP | 개설등록 이후 |
|---|---|---|
| 경로 **제시** ("임대 활용을 검토할 수 있습니다") | ✅ | ✅ |
| 물어볼 **곳의 종류** 안내 (세무사·법무사·공인중개사무소) | ✅ | ✅ |
| **공적 창구** 안내 (포항시 빈집정비 담당, 농촌 빈집은행) | ✅ | ✅ |
| 특정 **민간 업체** 연결 버튼 | ❌ | 별도 검토 |

`[임대운영 상담받기]`처럼 특정 사업자로 넘기는 버튼은 알선으로 읽힐 여지가 있다.
특히 `매각 → 중개`는 개설등록 전이라 더 민감하다.
PRD §2-A가 화면에서 "중개"라는 말 자체를 뺀 것과 같은 논리다.

**대신 폼 5번 답변이 쌓이면 어느 경로에 수요가 몰리는지 데이터가 남는다.**
그게 나중에 파트너십 협상 근거가 된다. 지금 급한 것은 연결이 아니라 그 데이터다.

### 진단서 철거 문구 — 반드시 정정

핸드오프 §2 2페이지에 이렇게 적혀 있다.

> 포항시 빈집 정비 지원을 받는 경우, 같은 규모 주택의 시 공고 기준 금액은 1,200만원입니다.

**PRD §2가 명시적으로 경고한 오류다.** 그대로 구현하면 소유주에게 부정확한 정보를 준다.
아래로 바꾼다.

> 포항시 빈집 정비는 두 계통입니다. 시 사업은 철거비를 부담하지만 보상은 없고
> 지상권 등기(읍·면 5년)와 공익용도 유지 의무가 따릅니다.
> 구 사업은 보조금 최대 200만원에 자부담 10%가 있습니다.
> 지붕이 슬레이트여서 석면 처리 절차가 따로 있습니다.

## 6. 저장 — Supabase 테이블 2개

`docs/설계.md` §5의 저장소 분리를 따른다.

```
applications                신청 (사람이 넣는 것)
  id                uuid
  address           text        입력 원문
  resolved_address  text        juso 가 정규화한 주소
  pnu               text
  match_quality     text        exact | road | fuzzy
  condition         text        집 상태 한 줄
  acquisition       text        취득 경위        ★신규
  ownership         text        소유관계          ★신규
  concern           text        걱정거리          ★신규 — 6경로 정렬 기준
  speed             text        희망 소요         ★신규
  channel           text        받을 방법 (필수)
  contact           text        전화번호 (필수·NOT NULL)
  email             text        이메일 (이메일 수신 선택 시)   ★신규
  created_at        timestamptz ISO 8601
  expires_at        timestamptz created_at + 6개월

reports                     진단서 (우리가 만드는 것)
  id                uuid        ← 이것이 URL 이 된다
  application_id    uuid
  version           int         '이 정보가 틀렸어요' 대응. 고친 진단서는 2
  verdict           text        possible | conditional | blocked
  axes              jsonb       6항목 판정 근거
  paths             jsonb       6경로 + 정렬 결과
  issued_at         timestamptz
```

**1:N인 이유** — 진단서 하단에 "틀린 항목을 알려주시면 고친 진단서를 보내드립니다"가 있다.
버전이 남아야 한다.

### 진단서는 누가 만드나 — 관리자 화면을 만들지 않는다

MVP는 사람이 손으로 작성한다(PRD §1). 관리자 페이지도 안 만들기로 했다(W15).
→ **Supabase 대시보드에서 직접 행을 입력한다.** 3건이면 충분하고 코드가 0줄이다.
관리자 화면은 신청이 주 10건을 넘을 때 만든다.

## 7. 진단서 뷰 — `/report/[id]`

핸드오프 §2 스펙대로 A4 2페이지. 인쇄/PDF가 1차 매체이고 화면에서는 반응형.

### 보안이 핵심이다

진단서에는 주소와 판정이 들어간다 — 개인정보다.

- `id`는 **순번이 아니라 uuid**. 추측으로 남의 진단서를 열 수 없어야 한다
- `robots: noindex` — 검색엔진에 색인되면 안 된다
- **목록 라우트를 두지 않는다** (제18조의2, 1차 원칙 승계)
- `expires_at` 경과분은 404

### 반응형

A4 고정폭을 쓰지 않는다. 820px 이하에서 폭 100% + 패딩 `28px 20px 32px`,
`26px 118px 1fr` → `24px 1fr`, `100px 1fr` → 1컬럼.
**390px에서 가로 스크롤이 생기면 안 된다.**

## 8. 전달

### 막힌 것 — 도메인 [진행 중]

Resend는 도메인 인증 전까지 **가입 계정 주소로만 발송**된다.
2026-09-04 실측에서 403 `validation_error`로 확인했다.
**소유주에게 보내려면 자체 도메인이 필요하다.**

| 방법 | 필요한 것 | 상태 |
|---|---|---|
| A. 도메인 인증 후 자동 발송 | 도메인 구매 + Resend DNS 레코드 | **구매 예정** |
| B. 수동 전달 | 없음. 링크를 복사해 문자·메일로 직접 | 즉시 가능 |

**B를 기본으로 하고 A를 병행한다.** 3건에 수동 전달은 컨시어지 원칙 그대로다.
도메인이 준비되면 `NOTIFY_FROM`만 바꿔 자동으로 전환한다.

### 도메인이 없으면 함께 못 하는 것

- 소유주에게 진단서 링크 자동 발송
- **접수 확인 메일** — 신청자는 완료 화면을 본 뒤 일주일 동안 아무 연락을 못 받는다.
  대기 구간의 불안을 메우려면 운영자가 직접 문자를 보내야 한다.
