## 실제 확인 범위

### 빌드와 기존 기능

- `npm run build`: 성공. TypeScript 검사·정적 페이지 생성 포함.
- 기존 핵심 모델 테스트 29개 성공: 즉시 진단, 미확인과 0 구분, 금액 계산, 지원 자격 미확정, 사진 처리, 공개 내용과 내부 메모 분리.
- 관리자 브라우저 검사 성공: 검색·필터·상세, 가상 DB 로그인과 처리 기록 저장, 공개 승인과의 분리, 조회 실패 안내, 로그아웃. 실제 DB와 이메일은 사용하지 않았다. [결과](../output/admin-qa/result.json)
- 기존 다중 lockfile에 따른 Next.js 루트 추정 경고가 남아 있다. 이번 디자인 변경에서 빌드 실패는 발생하지 않았다.

### 화면과 반응형

Chrome/Playwright에서 홈·예시 진단서·지원정보·조회 입력·추가 신청·개인정보·관리자 미리보기·관리자 설정 **8개 경로 × 320/375/600/768/1440px = 40개 초기 화면**을 확인했다.

- 주 문서 응답 200, JavaScript pageerror 0, 문서 및 검사한 표시 요소의 좌우 넘침 0.
- H1의 실제 렌더링 폰트가 모든 검사 화면에서 Pretendard Variable 웹폰트임을 확인했다.
- 600px 진단서에서 지원 영역과 나머지 고객 섹션 제목은 모두 22px.
- 모바일 홈 소개가 단어 중간에서 잘게 끊기던 문제를 전폭 설명으로 개선했다. 375px에서 주소 입력 상단은 약 580px. 이전 감사 약 641px보다 앞에 배치됐으며, 실제 사용자 전환율을 검증한 것은 아니다.
- 모바일 터치 에뮬레이션에서 신청 라디오의 흰색 → 옅은 녹색 전환과 테두리 변화를 확인했다.
- 고객 폼의 빈 필수 항목 오류·연결된 설명, 잘못된 사진 형식 거부, 로컬 테스트 이미지 추가·삭제를 확인했다. 정상 신청을 실제 DB에 저장한 검사는 아니다.
- 계산기의 빈칸·잘못된 값·가정값 초기화, 방향 선택, 하위 4개 화면의 홈 이동을 확인했다.
- 기본 검사 후 글자 200% 확대에서 진단서 헤더의 인쇄 버튼이 밀리는 문제를 발견해 작은 화면의 헤더 줄바꿈을 추가했다. 수정 후 375px에서 홈·진단서·지원정보·신청·관리자 미리보기의 root 글자 200% 확대 시 가로 넘침이 없었다. 진단서의 늘린 글자·단어 간격에서도 폭을 유지했다.

### 인쇄

설명용 예시를 A4 PDF로 출력하고 페이지 이미지를 확인했다. 본문·표·출처는 16 CSS px 이상으로 계산됐으며, 비교 카드·근거·지원 조건을 확인했다. 긴 지원 카드 전체를 한 페이지에 묶어 생기던 큰 빈 공간은 조건 단위로 나누도록 조정했다. 가로 화면의 버튼과 펼침 표시를 인쇄에서 제거했다. 실제 전화번호 링크는 검증용 PDF에서 ‘전화 문의’로 치환했다.

[검증용 예시 PDF](../output/design-system-2026-09-12/report-print.pdf). 실제 고객별로 더 긴 자료의 페이지 분할과 모든 프린터의 출력은 별도 확인 대상이다.

## 코드 검토에서 함께 확인한 것

- 공통 스타일로 합친 뒤에도 버튼·링크의 HTML 의미와 기존 이벤트를 유지했다.
- 관리자 primary의 hover가 보조 버튼의 옅은 배경을 상속하지 않도록 primary 변형을 공유했다.
- 진단서 하단 CTA와 지원정보 링크는 기존 전폭을 유지한다.
- 공유 Brand로 대체된 기존 페이지별 brand 스타일은 제거했다.
- 신청 오류 연결만 개선했으며 수집 항목·동의 내용·신청 액션·저장 방식·진단 규칙·권한은 변경하지 않았다.

## 남은 범위

- 실제 iPhone·Android 기기, iOS Safari, 화면낭독기 전체 흐름은 검사하지 않았다. 모바일 Chrome 에뮬레이션과 크기 변경으로 확인했다.
- root 글자 200% 확대·글자 간격 조정은 레이아웃 검사다. 브라우저의 모든 확대 방식이나 WCAG 전체 준수 판정을 뜻하지 않는다.
- 기존 페이지 프레임·광학 보정·일부 간격의 px는 남아 있다. 새 구성에는 공통 토큰을 사용한다.
- 실제 DB 연결·고객 사진 저장·이메일 발송은 이 작업의 검증 범위 밖이다.
- 일부 관리자 페이지 전환에서 prefetch 요청 취소가 기록됐다. 주 문서와 실행 오류 검사는 통과했으며, 모든 네트워크 요청이 0건 실패였다는 의미는 아니다.
