# 랜딩 정보 구조 (2026-10-30)

두 서비스는 방문자의 고민과 해야 할 행동이 달라 **페이지를 둘로 나눴다** (`/diagnosis`, `/management`). 사이트·도메인은 하나로 유지한다 — 운영자·개인정보처리방침·연락처를 한 곳에서 관리하고, 둘 사이를 오가는 방문자를 잃지 않기 위해서다. `/`는 짧은 갈림길만 맡는다. 광고는 각 랜딩으로 바로 보낸다.
두 페이지는 같은 순서를 따른다: 고객의 말 → 제공하는 도움 → 받는 것 → 진행 순서 → 현재 범위 → 주 행동(+ 누르면 일어나는 일).

## 첫 화면

| 항목 | 내용 |
| --- | --- |
| 누구를 위한 | 포항에 빈집이 있는 소유자·가족 (사는 곳 무관) |
| 핵심 문장 | 팔지, 고칠지, 돌볼지. 우리 집에 맞는 방법을 찾아보세요. |
| 주 행동 | 고민에 맞는 페이지 고르기 (두 갈래 카드 → `/diagnosis`, `/management`, 각 카드에 현재 상태 표시) |

## A. 빈집 진단 — 실증 참여 모집 (`/diagnosis`)

| 항목 | 내용 |
| --- | --- |
| 고객의 상황 | “계속 갖고 있을지, 고칠지, 팔거나 철거할지 모르겠어요.” |
| 제공하는 도움 | 집 정보, 선택지별 비용·조건, 다음 할 일을 담당자가 검토해 진단서로 정리 |
| 현재 이용 범위 | 포항 시범 참여 모집. 기본 자료 진단 무료, 현장 방문은 필요할 때 따로 상의. 법률·세무·구조 안전 판단과 실제 거래가·공사 견적은 대신하지 않음 |
| 주 행동 | `진단 참여 안내 보기` → `/participate` (조건 확인 → 주소로 집 찾기 → `/apply`) |
| 보조 행동 | `진단서 예시 보기` → `/example-report` (예시 끝에서 `/participate`로 복귀), 전화 문의 |
| 신청 후 결과 | 담당자가 연락해 진행 가능 여부와 결과 전달 일정을 알려 줌 → 사람이 검토한 진단서 전달 |

## B. 빈집 관리 — 수요조사 (`/management`)

| 항목 | 내용 |
| --- | --- |
| 고객의 상황 | “당장 팔 생각은 없는데, 멀어서 직접 챙기기 어려워요.” |
| 제공하려는 도움 | 정기 방문(월 1회 바깥 상태), 사진·메모 전달, 필요한 작업 확인 — 모두 준비 중 |
| 현재 이용 범위 | 서비스 준비·의견 조사 단계. 신청·결제·계약·방문 예약 아님. 요금·방문 범위 미정. 구조 안전 진단·긴급 출동 미포함 |
| 주 행동 | `관리 서비스 의견 남기기` → `/interest` |
| 참고 자료 | 방문 후 받게 될 소식 구상 (방문일·사진·메모·필요한 작업) — ‘구상’ 표시, 실제 보고 아님 |
| 응답 후 결과 | 전화번호(필수)로 담당자가 응답을 확인하고 연락. 정확한 번지는 받지 않음 |

## C. 참고 정보 (`/` 하단, 낮은 우선순위)

철거 후 세금 · 지원 조건 · 권리관계 확인 → `/resources`.

## 하지 않기로 한 것

- 랜딩에서 주소 입력 (주소는 `/participate`에서 안내를 읽은 뒤)
- 관리 설문을 진단 신청 우회 경로로 쓰기
- 고객 후기처럼 보이는 고민 카드 (고민은 첫 화면 갈래 카드의 문장으로만 사용)
- 업체용 업무관리 구독 노출

## 경로 정리

- `/diagnose`(예전 즉시 진단 입구) → `/diagnosis`로 이동
- `/care`는 가상 데이터 시연 화면이라 관리 랜딩으로 쓰지 않음
- 각 랜딩 첫 화면에 주 버튼을 한 번, 페이지 끝에 한 번 더 둔다

## 전국 수요조사 전환 (2026-10-31)

- 사이트 목적: 입소문, 수요 증명, 가격대 근거, 사례 파악. **설문·인터뷰는 전국, 진단 시범은 포항.**
- 포항 밖 진단 희망자 → `/interest?source=other-region` (같은 설문, 도입 문구만 ‘우리 지역 소식 받기’). 지역별 수요가 `source`로 남는다.
- 설문 추가 문항(모두 선택): 상속 정리 상태, 마지막 방문 시기, 현재 관리 비용, 가격 네 문항(너무 싸다/싸다/비싸다/너무 비싸다, 만 원), 인터뷰 참여 의향.
- 수요 신호 강도: 설문 응답 < 전화번호 < 인터뷰 수락 < 진단 신청. 설문 가격은 구매 의사가 아니다.
- 인터뷰 보상: 설문에는 보상 없음. 의향자 중 담당자가 골라 연락 → 30~40분 통화 → 모바일 상품권. 금액·인원은 사이트에 쓰지 않는다. 녹음은 별도 동의.
- 공유: ‘가족에게 이 페이지 보내기’ → `?utm_source=family-share` → 탭 저장 → 설문 `source`.
- DB: `supabase/migrations/20261031_care_interest_answers.sql` (`answers jsonb`, `interview_ok`). **적용 전에는 새 문항 응답이 저장되지 않는다.**

## 진단 전국 개방과 수치 증빙 (2026-10-31)

목적: 모두의 창업 다음 라운드 사업계획서의 수치 근거. 지인 인터뷰는 대표가 오프라인으로 따로 진행하고 사이트 데이터와 섞지 않는다.

- 진단: 자료 기반 진단은 전국, 현장 방문은 포항·경주권. 지원사업·시세 참고자료는 포항만 정리돼 있어 다른 지역은 확인처 안내. 신청 순서대로 연락.
- 방문자: Vercel Web Analytics (`app/layout.tsx`의 `<Analytics />`, 쿠키 없음). **Vercel 프로젝트 대시보드에서 Analytics를 켜야 집계가 시작된다.** 로컬 개발에서는 전송하지 않는다.
- 지표: `/admin/metrics` (관리자 전용). 진단 신청·설문 합계, 시도·주차·유입 경로·응답 분포, 가격 네 문항 중앙값/25~75%. `/admin/metrics/export`는 연락처 없는 집계 CSV.
- 전환율 = (진단 신청 + 설문 응답) ÷ Vercel 방문자 수. 기간을 맞춰 계산한다.
- 응답은 6개월 뒤 자동 삭제되므로 집계 CSV를 주기적으로 내려받아 보관한다.
