## 2. 확정된 흐름

```
[공개]  랜딩 → 신청 폼(주소·연락처·받을 방법) → "접수됐습니다"
                        │
                   DB에 pending 저장 (여기서 끝. 사용자 대기 없음)
                        │
[내부]  /report/[id] 를 열면
                        ├─ 자동 파이프라인 실행 (PNU → 1~5단계)
                        ├─ 결과를 초안으로 채움
                        └─ 6·7단계는 빈칸 → 현장 확인 후 직접 입력
                        │
                   확정 → 링크/PDF 전달 → 연락처 파기
```

**큐를 쓰지 않는다.** 폼 제출은 저장만 하고, 진단서 뷰를 열 때 파이프라인을 lazy 실행한다. Vercel 백그라운드 잡·Inngest·크론이 전부 불필요해진다. 발표 시연도 이 편이 자연스럽다 — 진단서 뷰를 여는 순간 자동 조회가 도는 게 보인다.

## 3. 판정 파이프라인

```
"포항시 남구 구룡포읍 병포리 123-4"
   │
[0] 주소 정규화 (카카오 로컬) → 법정동코드·본번·부번·산여부·좌표
[0.5] PNU 조립 (19자리)  ← 2·3·4단계의 조회 키
   │
   ├─[1] 건축물대장   ledger.json 룩업   주용도·사용승인일·위반건축물   ← 게이트
   ├─[2] 개별주택가격  data.go.kr API     공시가 1억 이하              ← 게이트
   ├─[3] 토지이용규제  data.go.kr API     용도지역·행위제한 → ③칸
   ├─[4] 연속지적도    VWorld WFS         도로 접함 → ②칸(맹지)
   └─[5] 정사영상      VWorld 타일        위성 이미지 (사람이 판독)
   │
[6][7] 사람이 확정 — 현장 확인 · 소유주 자유서술 → ①칸(미등기·공동상속)
```

**1·2단계는 판정이 아니라 게이트다.** 걸리면 "대상 아님"으로 즉시 종료하고 3단계 이후를 돌리지 않는다.

### PNU 조립 규칙

```
PNU(19) = 법정동코드(10) + 산여부(1) + 본번(4) + 부번(4)
          산여부: 1=일반, 2=산
```

⚠️ **산여부 코드 체계가 두 개다.** PNU는 `1/2`, 건축물대장 `platGbCd`는 `0=대지 / 1=산`. 같은 변수로 쓰면 산지 필지에서 조용히 틀린다. 구룡포·호미곶은 산지 필지가 많아 반드시 걸린다.

### 3등급 종합 (W3 우선순위: ① 법적 > ② 물리적 > ③ 규제)

```
불가     ① 또는 ②가 blocked
조건부   어느 축이든 unknown / suspect 존재
가능     ①②③ 전부 clear  (= 현장 확인 완료분만 가능)
```

7단계(등기)는 공개 API가 없어 **항상 unknown**이다. 따라서 자동 파이프라인의 최선은 `조건부 + 미확인 목록`이고, `가능`은 사람이 6·7단계를 채워야 나온다. 이는 결함이 아니라 설계다 — 디자인 가이드 §1의 "확인된 것은 진한 실선, 확인되지 않은 것은 옅은 점선"이 그대로 화면이 된다.

### 4단계 맹지 판정 — 공간연산이 필요 없어졌다

토지특성의 `roadSideCodeNm` 이 도로접면을 코드값으로 준다. 연속지적도 폴리곤을
받아 도로 필지와 교차 검사하려던 계획을 걷어냈고, **G2 게이트도 소멸했다**.

다만 이 값은 지적 기준이라 현황도로를 반영하지 못할 수 있다. `세로(불)` 등
좁은 접면은 `suspect` 로 두고 현장 확인(6단계)에서 확정한다.

## 4. 데이터 소스

**2026-09-04 확정.** 엔드포인트를 실호출로 검증했다. 키는 **두 개면 된다**.

| 단계 | 소스 | 오퍼레이션 | 키 |
|---|---|---|---|
| 0 | 주소 → PNU | 행안부 도로명주소 `addrLinkApi` | `JUSO_CONFM_KEY` |
| 1 | 주거용 판별 | NED `getLandCharacteristics` → `ladUseSittnNm` | `VWORLD_KEY` |
| 2 | 개별주택가격 | NED `getIndvdHousingPriceAttr` → `housePc` | `VWORLD_KEY` |
| 3 | 토지이용규제 | NED `getLandUseAttr` → `prposAreaDstrcCodeNm` | `VWORLD_KEY` |
| 4 | 도로접면(맹지) | NED `getLandCharacteristics` → `roadSideCodeNm` | `VWORLD_KEY` |
| 5 | 정사영상 | VWorld 타일 | `VWORLD_KEY` |
| — | 소유 정보(후보) | NED `getPossessionAttr` → `cnrsPsnCo`, `resdncSeCodeNm` | `VWORLD_KEY` |

베이스 URL: `https://api.vworld.kr/ned/data/{operation}?key=&domain=&pnu=&format=json`

**`DATA_GO_KR_KEY` 는 판정 파이프라인에 필요 없다.** 같은 국가공간정보 데이터를
data.go.kr 과 VWorld 가 각자 제공하는데, VWorld 쪽이 4·5단계까지 같은 키로 덮는다.
data.go.kr 이 필요한 유일한 경우는 '단독/다가구 매매 실거래가'이며, 이는 판정이 아니라
발표 근거 보강용이다(워크시트 증거 2등급 → 3등급 승격).

### 세움터 대량 다운로드는 선택사항이 됐다

`ladUseSittnNm`(단독/주상용/답/전기타)으로 주거용 판별이 되므로 1단계 게이트를
대량 자료 없이 칠 수 있다. 아래는 규모를 키울 때의 이점이며 지금은 급하지 않다.

| | 건축물대장 API | 세움터 대량 |
|---|---|---|
| 키 발급 대기 | 있음 | **없음** |
| 호출량 제한 | 개발계정 일 한도 | **없음** |
| 발표 중 장애 | 가능 | **불가능** |

포항 단독주택 5,851호 규모라 JSON 룩업으로 충분하다. API는 대장에 없는 주소의 폴백으로만 쓴다.

### data.go.kr 함정 3가지

1. **serviceKey 이중 인코딩** — 포털이 인코딩/디코딩 키를 둘 다 준다. `.env`에는 **디코딩 키**를 넣고 한 번만 인코딩한다. `URLSearchParams`에 그냥 넣으면 `%2B` → `%252B`가 되어 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`.
2. **`_type=json`을 줘도 오류일 때는 XML로 온다** — 응답 첫 글자가 `<`인지 보고 분기.
3. **CORS 차단** — 브라우저 직접 호출 불가. 반드시 서버(Route Handler)에서.

### 공공데이터 CSV 인코딩

국내 공공 CSV는 대부분 **EUC-KR/CP949**다. UTF-8로 읽으면 한글이 깨진다. 파서가 BOM·인코딩을 자동 감지한다.

## 7. 전달 — 문자에 함정

국내 SMS API는 **발신번호 사전등록**이 필수이고 서류 심사에 며칠 걸린다. 14일 일정에서 위험하다.

- **이메일** — Resend 자동 발송 (5분이면 붙음)
- **문자** — 본인 휴대폰에서 링크를 직접 보내는 **수동 처리**

폼 선택지는 그대로 두고 내부 처리만 다르게 한다. 30~50호 규모에서 수동은 부담이 아니며, 어차피 컨시어지다. 발신번호 등록은 오늘 신청해두고 되면 그때 자동화한다.

PDF는 `/report/[id]`에 `@media print`만 얹는다. 라이브러리 불필요.

## 8. 디자인 제약 (가이드 v0.3 준수)

- **모바일 우선.** 타겟이 40~70대이며 대부분 모바일로 들어온다. W15의 "모바일 최적화 안 함"은 이 가이드로 덮는다
- **자격 표기 전면 금지.** "공인중개사·중개사·중개"를 화면에 쓰지 않는다 (푸터 고지 문구는 예외). 신뢰는 *가서 봤다는 사실 + 항목별 출처·확인일 + 못 하는 것 먼저 말하기*로 세운다
- **판정 3등급에 신호등 색 금지.** 같은 청록의 명도 3단
- **점선 = 미확인, 실선 = 확인**
- 색은 `@theme` 토큰으로만 참조 (`bg-deep`), 하드코딩 금지
- 금지어: 매물 · 시세 · 견적 · 컨설팅 · 솔루션 · 플랫폼 · 혁신 · AI 기반

> ⚠️ v9 워크시트 FINAL 12번 칸은 아직 차별점을 "법적 진입장벽(공인중개사 자격)"으로 적고 있어 가이드 v0.3과 어긋난다. 별도 갱신 필요.

## 9. 법적 제약

- **제18조의2** — 단일 필지 조회만. 여러 물건을 목록·지도에 뿌리지 않는다. 라우트에 목록 경로를 두지 않는다 (`/report/[id]`만)
- **개설등록 전 진단서 발급의 적법성 [미확인]** — 공개 배포 전 확인 필요. 가이드 v0.3의 자격 표기 삭제가 1차 대응
- **개인정보** — 연락처는 전달 목적으로만 수집하고 발송 후 파기(`contact_purged_at` 기록). 주소는 등기부와 결합 시 소유주 특정이 가능하므로 로그·GA4에 남기지 않는다

푸터 고지:
> 본 서비스는 공개된 공적 자료와 현장 확인을 근거로 빈집의 처분 가능성을 정리해 제공하며, 중개대상물의 표시·광고나 거래 알선을 하지 않습니다.
