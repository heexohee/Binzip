# 진단 체계 4축 재편 — 설계

작성 2026-09-06 · 상위 문서 `docs/설계.md`(1차), `docs/설계-2차-진단서와-행동경로.md`(2차)

---

## 0. 왜 고치나

현행 3축(`legal` / `physical` / `regulatory`)은 **권리관계를 담을 자리가 없고 세금은 아예 없다.**
타깃을 「상속받은 오래된 시골 단독주택」으로 좁힌 이상 이 둘이 빠지면 진단이 성립하지 않는다.

### 0.1 용어 정정 — 대지권이 아니다

**대지권은 집합건물 개념이다.** 「집합건물법」 §20의 대지사용권으로 아파트·다세대·연립 등기부에
토지 지분이 붙어 있는 형태를 말한다. **단독주택에는 대지권이 존재하지 않는다.**
단독주택은 토지등기부와 건물등기부가 애초에 별개로 두 개 있다.

따라서 우리가 볼 것은 대지권이 아니라 아래 넷이다.

| 사유 | 왜 생기나 | 결과 |
|---|---|---|
| **미등기 건물** | 60~80년대 시골집. 건축물대장은 있는데 건물등기부가 없음 | 이전등기 불가 → **사실상 매각 불가** |
| **상속 미등기** | 부모 명의 그대로 | 소유권은 이미 상속인 것(민법 §187). **다만 처분하려면 등기 선행** |
| **토지 소유자 ≠ 건물 소유자** | 종중 토지, 형제 명의 토지, 국·시유지 위의 집 | 토지사용 권원 확인 필요 |
| **법정지상권** | 위 상황에서 철거 특약이 없었던 경우 | 민법 §366 / 관습법상. 건물은 지키나 매수인 설명 부담 |

심각도는 **미등기 > 상속 미등기 > 토지≠건물 > 지상권** 순이다.
지상권은 "복잡하지만 집은 지킨다"이고, 미등기는 "팔 수가 없다"이다.

### 0.2 데이터가 준 기회

`src/sources/possession.ts`가 가져오는 것은 **전부 「토지」 정보**다. 건물이 아니다.
건물 쪽이 안 보이는 것이 오히려 기회다 — **토지 데이터와 소유주 진술을 대조하면 불일치가 드러난다.**

## 1. 축 — 4개, 그중 2개만 등급을 정한다

```ts
// src/verdict.ts
export type Axis = 'rights' | 'tax' | 'property' | 'market'

export const AXIS_LABEL: Record<Axis, string> = {
  rights:   '① 권리',
  tax:      '② 세금',
  property: '③ 건물·토지',
  market:   '④ 시장·관리',
}

/** 등급을 결정하는 축. 나머지 둘은 서술과 Decision 정렬에만 쓴다. */
const GATING: Axis[] = ['rights', 'property']
```

②세금·④시장도 **축 판정(verdict)은 낸다.** `combine()`이 등급을 계산할 때만 `GATING`을 본다.

> **왜 4축 전부가 등급에 참여하면 안 되나**
> 세금이 나쁘다고 거래가 막히지는 않는다. 세금은 *할 수 있느냐*가 아니라
> *어느 쪽이 유리하냐*를 바꾼다. 시장성도 같다.
> ①③은 **가능성을 막는 축**, ②④는 **선택을 정하는 축**이다.

## 2. 등급 — 4개

```ts
export type AxisVerdict =
  | 'clear' | 'unknown' | 'suspect' | 'precondition' | 'blocked'
//                                     ^^^^^^^^^^^^ 신규

export type Grade = '가능' | '조건부' | '선행필요' | '불가'
//                            ^^^^^^^^ precondition 이 만드는 등급
```

심각도 `clear 0 → unknown 1 → suspect 2 → precondition 3 → blocked 4`

| verdict | 뜻 | 등급 | 예 |
|---|---|---|---|
| `precondition` | **절차를 밟으면 풀린다** | 선행필요 | 미등기, 공유 미합의 |
| `blocked` | 지금 구조로는 어렵다 | 불가 | 맹지, 개발제한구역 |

> **왜 나눴나**
> 미등기를 그냥 `blocked`로 두면 등급이 `불가`가 되고 매각·임대 경로가 전부 닫힌다.
> 논리는 맞지만 메시지가 틀렸다. 해야 할 말은 "불가"가 아니라
> **"보존등기 하나 하면 팔 수 있습니다"**다.
> 해결형 판정이야말로 이 서비스에서 가장 값어치 있는 출력이고,
> 그대로 법무사 연결(§8)로 이어진다.

### 2.1 두 개의 자물쇠

**자동 판정은 위로도 아래로도 끝까지 못 간다.**

```
자동만으로  '가능'      ✗   fieldVerified    가 필요 (현행)
자동만으로  '선행필요'   ✗   registryVerified 가 필요 (신규)
```

이유는 데이터에 있다. **`hasBuilding === false`는 "미등기"가 아니다.**
그건 *건축물대장*에 없다는 뜻이고, 시골집에서 훨씬 흔한 것은
**대장은 있는데 등기부가 없는** 경우다. 공개 API로는 구분되지 않는다.

따라서 `precondition`은 **사람이 등기소에서 확인했을 때만** 찍힌다.
자동은 `suspect`("상속 이력이 있습니다, 등기 확인이 필요합니다")까지다.
예외는 맹지처럼 토지특성 데이터로 확정되는 `blocked`뿐이다.

> **발표 영향** — `선행필요` 화면은 자동 데모로 나오지 않는다. 시연하려면 임장 1건이 필요하다.

## 3. ①권리축

### 3.1 자동으로 잡히는 것

| Red Flag | 근거 | 상태 |
|---|---|---|
| 토지 공유 | `coOwnerCount >= 2` | 기존 `L-COOWNER` → axis 변경 |
| 토지 상속 이력 | `ownershipCause` = 상속 | 기존 `L-INHERIT` → axis 변경 |
| 건축물대장 없음 | `hasBuilding = false` | 기존 `P-NOBUILDING` → axis 변경 |
| **토지 소유자가 개인이 아님** | `ownerType` = 국유지·시유지·법인·종중 | **신규** |
| **진술 ↔ 토지대장 불일치** | 폼 `ownership`='단독' + `coOwnerCount >= 2` | **신규** |

```jsonc
{ "id": "R-LANDOWNER-TYPE", "axis": "rights",
  "when": { "field": "ownerType", "op": "not-matches", "value": "개인" },
  "verdict": "suspect",
  "label": "토지 소유",
  "reason": "토지 소유구분이 '{ownerType}'입니다. 건물과 토지의 소유자가 다를 수 있습니다.",
  "nextStep": "토지 등기사항증명서로 소유자를 확인해야 합니다. 다르다면 지상권·임차권 등 토지사용 권원이 있는지 봐야 합니다.",
  "source": "토지소유정보" }

{ "id": "R-CLAIM-MISMATCH", "axis": "rights",
  "when": { "field": "ownershipClaimMismatch", "op": "eq", "value": true },
  "verdict": "suspect",
  "label": "지분",
  "reason": "토지대장에는 공유인이 {coOwnerCount}명으로 기재되어 있습니다. 알고 계신 것과 다를 수 있어 확인해보시면 좋겠습니다.",
  "nextStep": "토지대장은 갱신이 늦을 수 있습니다. 등기사항증명서로 현재 지분 관계를 확인해 보시기를 권합니다.",
  "source": "토지소유정보" }
```

> **`R-CLAIM-MISMATCH` 문구 원칙**
> 소유주 진술을 데이터로 **반박하지 않는다.** 대장이 최신이 아닐 수 있고,
> 틀렸을 때 잃는 신뢰가 크다. "아니네요"가 아니라 "기록은 이런데 한번 보시죠"로 쓴다.
> 우리가 틀렸을 여지를 문장 안에 넣어둔다.

`ownershipClaimMismatch`는 파생 필드다. `pipeline.ts`가 신청 정보를 facts에 합쳐 넘긴다
(폼 진술과 공공데이터를 대조하는 첫 룰이라 지금 없는 배선이 필요하다).

### 3.2 사람이 등기소에서만 확인하는 것

`registry_note` 자유 텍스트 → 4칸 구조화.

```
□ 건물등기부          있음 / 없음(미등기)     → 없음이면 precondition
□ 토지 = 건물 소유자   같음 / 다름            → 다르면 지상권 확인 필수
□ 지상권·임차권        없음 / 있음(내용)
□ 근저당·가압류        없음 / 있음(내용)
```

2번이 "다름"이면 3번이 자동으로 핵심 질문이 된다. 없으면 법정지상권
(민법 §366 / 관습법상) 성립 여부를 따져야 하고 그것은 법무사 영역이다.

### 3.3 등기 4칸 → 판정 (`registryVerified`의 정의)

`precondition`은 **rules.json 이 만들지 않는다.** 등기 입력에서 직접 나온다.
`rules.json`은 공개 데이터만 다루고, 등기는 공개 데이터가 아니기 때문이다.

```ts
/** 4칸이 모두 채워졌을 때만 참. §2.1 의 아래쪽 자물쇠. */
registryVerified = 건물등기 !== null && 소유자일치 !== null
                && 지상권 !== null && 근저당 !== null
```

`registryVerified === false` 면 ①권리축은 `unknown` 에 머문다(현행 `L-REGISTRY` 와 같다).
참이 되면 아래 표로 축 판정이 정해진다.

| 입력 | verdict | 등급 기여 |
|---|---|---|
| 건물등기부 **없음(미등기)** | `precondition` | 선행필요 |
| 소유자 **다름** + 지상권·임차권 **없음** | `precondition` | 선행필요 |
| 소유자 **다름** + 지상권·임차권 **있음** | `suspect` | 조건부 |
| 근저당·가압류 **있음** | `suspect` | 조건부 |
| 넷 다 깨끗 | `clear` | — |

여러 개가 걸리면 §2 의 심각도 순위대로 가장 나쁜 것이 축 판정이 된다
(`summarize()` 의 기존 동작과 같다).

**소유자 "다름" 하나만으로는 `precondition` 이 아니다.** 지상권이 있으면 건물은 지켜지고
매각도 가능하다 — 매수인에게 설명할 부담이 남을 뿐이라 `suspect` 다.
권원이 아예 없을 때만 선행 절차가 필요하다.

## 4. ②세금축

### 4.1 보유세와 처분세는 난이도가 다르다

| | 필요한 입력 | 자동 |
|---|---|---|
| **재산세 (보유)** | 공시가격 — 이미 있음 | **가능** |
| **양도세 (처분)** | 다른 주택 보유·취득시기·보유기간·상속개시일 | 불가 |

**MVP는 재산세만 자동화한다.** 양도세는 체크포인트 서술만 하고 계산하지 않는다.
폼은 건드리지 않는다(9문항 유지).

> **왜 양도세 분기를 안 짜나**
> 상속주택 특례만 해도 상속개시일·일반주택 취득시점·동거봉양으로 갈라지는데,
> 실제 신청자를 받아보기 전에는 어느 가지에 몰리는지 알 수 없다.
> 데이터 없이 세법 분기를 설계하는 것은 YAGNI 위반이다.
> 10건쯤 받으면 대부분 같은 케이스일 것이다 —
> *"부모님 돌아가시고 형제끼리 명의 정리 안 된 시골집, 나는 도시에 아파트 한 채"*.

### 4.2 재산세 — 비율은 코드가 아니라 데이터로

```
과세표준 = 공시가격 × 공정시장가액비율
재산세   = 과세표준 × 세율  +  지방교육세(본세 20%)  [+ 도시지역분]
```

**공정시장가액비율은 시행령으로 매년 바뀐다.** `rules.json`과 같은 원리로 분리한다.

`src/rules/tax.json`
```jsonc
{ "version": "2026",
  "note": "지방세법 §111·§111의2. 비율과 세율은 매년 확인해 갱신한다.",
  "fairMarketRatio": { "single": 0.43, "general": 0.60 },
  "rates": {
    "single":  [ { "upto": 60000000,  "base": 0,      "rate": 0.0005 },
                 { "upto": 150000000, "base": 30000,  "rate": 0.0010 },
                 { "upto": 300000000, "base": 120000, "rate": 0.0020 },
                 { "upto": null,      "base": 420000, "rate": 0.0035 } ],
    "general": [ { "upto": 60000000,  "base": 0,      "rate": 0.0010 },
                 { "upto": 150000000, "base": 60000,  "rate": 0.0015 },
                 { "upto": 300000000, "base": 195000, "rate": 0.0025 },
                 { "upto": null,      "base": 570000, "rate": 0.0040 } ] },
  "localEduTaxRate": 0.20,
  "urbanAreaRate": 0.0014,
  "urbanZones": ["주거지역", "상업지역", "공업지역", "녹지지역"] }
```

**도시지역분은 `zone1`으로 자동 판별한다** — `urbanZones`에 걸리면 부과,
관리·농림·자연환경보전지역이면 미부과. 계획관리지역 필지에는 붙지 않는다.

`src/tax.ts` 는 `housePrice`와 `zone1`을 받아 `{ single, general, urbanIncluded }`를 돌려준다.
`single`은 1세대1주택 특례(공시 9억 이하) 적용값, `general`은 표준세율 적용값이다.

검산 — 공시가격 60,800,000원 · 계획관리지역

```
1주택  26,144,000 × 0.05% = 13,072 + 지방교육세 2,614 =  15,686원/년
일반   36,480,000 × 0.10% = 36,480 + 지방교육세 7,296 =  43,776원/년
```

> **⚠️ 착수 전 확인**
> 위 비율·세율표는 발행 전에 **위택스 지방세 미리계산**과 대조해 검증한다.
> 공정시장가액비율(1주택 43/44/45%)과 특례세율 구간은 개정이 잦다.
> 진단서에는 반드시 **"추정"**을 명시한다.

### 4.3 진단서에 나가는 문장

```
보유세   연 약 1.6만 ~ 4.4만원 (추정)
         1세대1주택이시면 1.6만원, 다른 집이 있으시면 4.4만원 수준입니다.
         공시가격 6,080만원 기준 · 종합부동산세는 대상이 아닙니다.

처분세   다른 집이 없으시다면 — 1세대1주택 비과세 요건(2년 보유 등)을 보시면 됩니다.
         다른 집이 있으시다면 — 상속주택 특례(소득세법 시행령 §155②)와
         농어촌주택 특례(조특법 §99의4) 두 가지를 확인해볼 수 있습니다.
         구체적인 세액은 이 진단서에서 계산하지 않습니다.
```

**핵심 메시지는 안심이다.** 소유주는 "재산세가 계속 나간다"를 막연한 공포로 갖고 있는데
실제로는 10년 보유해도 20~40만원이다. 세금축이 내리는 판정은
*"보유세 때문에 팔아야 한다"*가 아니라 **"보유세는 문제가 아니다, 관리 안 하는 게 문제다"**다.

## 5. 항목 — 평면 6개 → 계층 4축 × 10항목

분량은 늘지만 **축 헤더가 판정을 지므로 훑는 사람은 4줄만 봐도 된다.**

```
① 권리                                    [확인 필요]
     등기            휴먼 4칸 (§3.2)
     토지 소유       ownerType · coOwnerCount · ownershipCause      신규 노출

② 세금                                    [양호]
     보유세          연 약 1.6만 ~ 4.4만원                          신규·자동
     처분세          조건부 서술 (계산 없음)                         신규

③ 건물·토지                                [조건부]
     건축물          현행 ① 그대로
     진입로          현행 ③ 그대로
     규제            현행 ④ 그대로
     현장 상태       현행 ⑤ 그대로

④ 시장·관리                                [—]
     공시가격        현행 ② 그대로
     관리 부담       이행강제금 · 최소 유지                          신규
```

**현행 6항목은 전부 살아남는다.** ③에 4개가 몰리는 것은 그쪽 데이터가 제일 많아서다.

### 5.1 인쇄 절단선 — 미리 정해둔다

10항목은 A4 한 장에 약 26~28줄이다(현행 6항목 15줄).
**넘칠 경우 ④시장·관리를 2페이지(경로 쪽)로 내린다.** ①②③이 1페이지에 남는다.

이 절단선을 고른 이유: ④는 유일하게 등급에 참여하지 않고(§1),
내용상 "그래서 뭘 할까"에 가까워 경로 쪽과 붙어도 자연스럽다.

## 6. 경로 — 6 → 7

| 키 | 이름 | 변경 |
|---|---|---|
| `rights` | 권리정리 우선 | 이름만 |
| `sell` | 매각 | — |
| `rent` | 임대 | — |
| `repair` | 정비 | 이름만 |
| `demolish` | 철거 | — |
| **`secondhome`** | **보유·세컨드하우스** | `hold`에서 **적극형으로 재작성** |
| **`manage`** | **관리** | **신규 분리** |

현행 `hold`의 *"그대로 두셔도 됩니다. 다만 재산세는 매년 나갑니다"*라는 소극적 한 줄이
두 개의 다른 결론으로 갈라진다.

```
보유·세컨드하우스
  10년 보유하셔도 재산세 총액은 약 16만원입니다.
  보유 비용이 계획을 접을 수준은 아닙니다.
  공시가격 4억원 이하라 2027.1.1 취득분부터 세컨드홈 특례 대상입니다.

관리
  비워두시더라도 최소한의 관리는 필요합니다.
  「빈 건축물 정비 특별법」의 관리의무·이행강제금이 도입되면
  방치 비용이 재산세보다 커집니다.
```

§4의 재산세 숫자가 `secondhome`의 근거가 된다. 두 경로가 **"보유해도 싸다"**와
**"방치는 비싸다"**로 명확히 갈린다.

### 6.1 정렬

```ts
if (grade === '선행필요')  rights → 0순위,  sell·rent → 닫힘

CONCERN_TO_PATH = {
  '세금': 'sell', '등기·상속': 'rights', '건물 상태': 'repair',
  '관리': 'manage', '매각 가능성': 'sell', '활용 방법': 'rent',
}
```

`'관리'`가 제 경로를 갖는다(전에는 `hold`로 뭉뚱그려졌다).

`'세금'`은 `sell`로 보낸다. 세금을 걱정하는 분이 꼭 팔고 싶은 것은 아니지만,
②축이 재산세 숫자로 이미 안심시키므로 경로 정렬까지 분기시키지 않는다.
축 순서를 concern에 따라 바꾸는 것은 복잡도 대비 이득이 없어 하지 않는다.

## 7. 마이그레이션 — 코드 0줄

저장된 `axes` jsonb는 `legal` / `physical` / `regulatory`인데,
새 구조에서 `regulatory`와 `physical`이 둘 다 `property`로 합쳐져 매핑이 손실된다.

**변환 코드를 쓰지 않는다.** 테스트 row를 정리하고 검토화면의 기존 `재실행` 버튼을 쓴다.
발행된 1건도 재실행 후 재승인한다.

```sql
delete from applications where condition like '%테스트%';
```

`registry`는 컬럼을 **지우지 않고 추가**한다.

```sql
alter table public.reports add column if not exists registry jsonb;
-- registry_note / registry_checked_at 은 남긴다 (옛 row 폴백 읽기)
```

## 8. 수익 구조 — 진단이 아니라 연결을 판다

**프리미엄을 "양도세 진단"으로 잡으면 안 된다.**
무료 정보 제공은 회색이지만, **유료로** 세액을 산출하면 세무사법 §2가 정의하는
세무대리(조세에 관한 상담·자문)에 정면으로 들어간다. 유상성이 있으면 판단이 쉬워진다.

프레임을 한 칸 튼다.

```
빈집이력서 (진단)  →  ①권리 미등기·상속미등기  →  법무사
                   →  ②처분세 체크포인트       →  세무사
                   →  ③슬레이트·구조           →  시공사
```

우리가 파는 것은 **판단이 아니라 진입점**이다. 진단서가
*"상속등기가 안 돼 있어 이 상태로는 매각이 안 됩니다"*까지 말해주면
소유주는 법무사가 필요하다는 것을 처음으로 알게 된다. 자격 문제가 없다.

①권리축이 세금축보다 연결 가치가 크다. 미등기·상속미등기는 **반드시 전문가를 거쳐야**
풀리는 반면 재산세는 안 거쳐도 된다.
