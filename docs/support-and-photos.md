# 공적 지원과 사진 첨부 (2026-09-11)

## 구현 범위

- 실제 진단서와 구성 예시에서 같은 `SupportCards` / `src/supports.ts` 사용.
- 포항시 빈집정비사업 공식 공고(2026-03-11 게시): 신청 2026-01-28부터 예산 소진 시까지, 읍면동 행정복지센터·공동주택과, 054-270-3608. 첨부 HWP의 세부 한도·선정 조건은 미검증이므로 금액을 확정하지 않음.
- 슬레이트 사업 존재는 포항시의회 2026-07-22 공식 회의록에서 확인. 현재 접수·예산과 개별 자격은 미확인.
- 확정 필지의 지역만 확인 표시. 건축물 존재·구조명·사진에서 지원 자격 또는 석면 여부를 도출하지 않음. 타지역 확정 필지에는 포항 사업을 배정하지 않음. 확인 후 45일 초과 또는 다음 연도에는 재확인 표시.
- 사진: 선택 최대 6장. 브라우저에서 1600px 이하·512KiB 이하 JPEG로 변환, 서버에서 다시 디코딩·재인코딩해 EXIF/GPS·원래 파일명 제거. 원본은 보관하지 않음.
- 선택 동의 검증 후 신청과 사진을 단일 DB 트랜잭션으로 저장. DB 실패 시 사진을 버리고 접수 성공으로 처리하지 않음.
- 관리자만 첨부 사진을 열람. 사진 URL도 관리자 인증·신청 매칭·만료 확인을 거침. 공개 리포트에는 접수 수만 표시. 외부 AI 분석은 구현 범위에 포함되지 않음.

## 운영 반영 전

1. 기존 `supabase/schema.sql`이 적용된 DB에 `supabase/migrations/20260911_application_photos.sql` 적용.
2. 기존 SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY / ADMIN_TOKEN 설정 유지. 새 버킷이나 외부 저장소 키는 불필요.
3. 만료 삭제는 기존 `purge_expired()`로 신청 삭제 시 사진도 FK cascade로 삭제. 기존 주기 실행 여부를 운영 DB에서 확인할 것. 수동 삭제 요청도 applications 행 삭제로 함께 처리.
4. 소량 MVP를 위해 사진을 비공개 `bytea`로 보관(신청당 최대 3MiB). 관리자 목록은 이미지 본문을 조회하지 않음. 데이터 증가 시 저장량과 보관 기간을 기준으로 별도 객체 저장소 이전 검토.
5. 고객 사진과 메일을 이용한 실접수 테스트는 운영 환경에서 별도 확인. 로컬 미리보기는 실제 DB 자격증명을 사용하지 않음.

브라우저 확인: 테스트 사진 선택·미리보기·삭제·동일 사진 재선택, 합계 6장 초과 차단, 사진 동의 검증, 저장소 미연결 시 접수 실패 안내, 오류 뒤 주소·연락처·사진·동의 유지. 390px 화면에서 신청 폼과 지원 카드의 가로 넘침 없음. 리포트 화면 브라우저 오류 없음. HEIC는 현재 지원하지 않으며 JPG 변환 안내를 표시함.

지원 출처는 각 카드에서 원문을 열 수 있음. 지원금은 견적의 확정 할인액으로 사용하지 않으며, 지급·선정·예산 잔액을 보장하지 않음.
